# 密室夺宝：有限检测、藏点转移与地图标注

这是电脑上的离线策略仿真。双方预存地图；策略使用自身位置、地图先验、有限检测及检测历史。未检测到的对手真值不会传给策略。画面显示双方真值用于复盘，裁定器使用真值判断接触。

## 打开与重新生成

直接双击 `replay.html` 即可离线观看，不需要服务器或外网。也可以使用本机入口 http://127.0.0.1:8765/replay.html 。本机服务停止时，直接打开 HTML 或在仓库根目录运行：

```powershell
python -m http.server 8765 --bind 127.0.0.1 --directory Tools/TreasurePursuitSimulator
```

修改参数后，在仓库根目录运行：

```powershell
python Tools/TreasurePursuitSimulator/simulate.py --seeds 1
python -m unittest discover -s Tools/TreasurePursuitSimulator
node Tools/TreasurePursuitSimulator/qa/verify_annotations.cjs
```

仿真只使用 Python 标准库。`--sweep` 额外比较 6 倍与 7 倍速度，`--seeds` 增加随机漏检样本。生成 `report.json`、`replay.html`、`escape_routes.json` 和 `map_annotations.json`。HTML 内嵌回放、标注脚本与地图，不依赖旁边的脚本文件；HTTP 页面导出配套 JSON，直接打开 HTML 则导出内嵌 JSON。重新生成后刷新网页。

## 这次策略修改

小偷过去每到一个网格细分点就重算远期路线，相对检测方向改变时又清除原计划，容易在同一条横线上反复折返。现在选择通往明确路口或藏点的完整路线，持续执行到目标；只有当前新检出的威胁显示下一段即将交会时，才提前换路。允许原路后退，后退与转弯都按实际等待成本比较。

针对截图对应位置 `(3,2)`、警方从右侧接近的复现测试，智能与预设两种模式均选择先到 `(3,1)`，再到 `(2,1)`，即向上再左转。另一个横线复现测试选择先向远端撤离再转下，不在下个节点立即反向。测试复现的是具体几何状态；修改策略后原回放的秒数不再一一对应。

藏点只选环路内的真实直角拐弯、T 型或十字路口，排除死路、普通直道细分点及宝藏点；所在整条直道跨度至多三格，至少有两条不通入单出口封闭环路的环路出口；排除仅通过一个口连接外界的无分岔环路及其入口藏点。候选评分考虑远离警方预计取宝来路、警方到可检测位置的行驶与拐弯耗时、附近分岔、重复停靠和转移成本。路线先比较近期交会风险，再比较分离方向及目标位置，不把直线距离当作唯一依据。当前检测会改变区域偏好；未检测时只使用先验，不能知道警方真实位置。

新增第七个场景 **“两格检测 · 定点藏匿与下一藏点转移”**：更重视让警方搜索和拐弯的代价，到达藏点后保持停靠，实际检测到警方才撤往下一藏点。原藏身模式也保持“未检出不主动离开”的停靠规则。刚暴露的藏点有 30 秒冷却期。连续逃跑使用环路内的有限目标路线；预设模式使用无重复节点的路线卡。相同条件下两种模式可能选出同一路线，当前示例中两组藏身智能与预设结果相同。

警方统一三格检测。没有线索时优先选择能够覆盖更多尚未检查候选位置的观察点，计入行驶、转弯及重复路段的代价。完整覆盖一轮后再开始新一轮，必要的过路不禁止。检出立即追踪；漏检后保留最后检测位置和方向线索，若尚未越过则先到最后位置，再沿最后方向查到直道末端后恢复搜索，或线索超过 12 秒时恢复搜索，不会因漏检返回初始取宝路线。

完整死路支路的节点及段中点均在检测范围内时，连续三次未检出后标记已查，可跳过驶入；新的侧向检出仍优先返回核查。保留连续三次确认是为了减小单次漏检的影响，并不是对实物空路的确定性证明。藏点与搜索路线都是启发式选择，未证明全局最优。

## 节点与路段标注

沿用 `../TreasureRoutePlanner/map.json` 的全部连接与长度：**88 个节点、106 条直线路段、121 个原图节点对应项**。压缩只合并直道上的普通细分点，不增加、删除或改接道路。每条原图边恰好属于一条导出路段，全部标注节点对之间的最短距离保持不变。

- “显示节点编号”和“显示路段信息”分别控制标注；节点及 N001 等编号默认开启，路段信息默认关闭。警方蓝色实线、小偷橙色虚线保留，车辆绘制在标注上层。
- 节点包括直角、T 型、十字、端点、双方出生点和宝藏点，用颜色及形状双重区分，并有图例。
- 点击节点查看编号、类型、格坐标、推算米坐标、原图键及每个相邻路段的长度、方向、相邻节点；点击路段查看两端及正反方向。下拉框可直接选择节点。
- 标签避开车辆、重要路口和其他标签。拥挤时部分路段标签省略，但道路仍可点击，完整对应关系仍在 JSON 内。手机开启标注后可单独横向滑动地图，也可用节点下拉框查看详情。
- 例如 `N023=(3,2)`，向北经 `S021` 到 `N012`，向东经 `S035` 到 `N024`，向南经 `S036` 到 `N031`，长度各 0.30 米。
- 藏点以真实节点编号显示，不放在路段中间。原图普通细分点，例如 `(4,3)`，仅以所在路段和距端点距离表达，不赋予可识别路口身份。
- `N005=(5.5,0)` 是宝藏任务位置，位于直道上，明确注明不是新增灰度路口。出生点也保留其端点几何类型。

所有长度沿用原图 0.3 米格距，**尚未实地标定**。坐标 x 向右、y 向下。相同形状的路口不能独立确定全局位置；后续定位仍需结合路口序列、行进方向和里程，识别特征需实车验证。

### JSON 与稳定编号

`map_annotations.json` 包括：

| 字段 | 用途 |
| --- | --- |
| `nodes` | 节点编号、原图键、坐标、全部类型、物理几何类型、邻接表、是否道路特征点 |
| `segments` | 路段编号、两端、长度、半格整数刻度、正反方向、原图节点序列与里程 |
| `original_node_mapping` | 全部原图节点对应的标注节点编号（或 null）、所在路段及距两端距离 |
| `identity_registry` | 编号登记表，供后续生成复用；不删除已登记编号 |
| `calibrated` / `length_note` | 未标定状态及长度来源 |

第一次按固定坐标顺序编号，之后读取已有导出文件中的登记表，保留旧编号并递增分配新编号；不要删除登记表后再更改地图，否则无法保证跨地图版本的旧编号。仅重新生成相同地图、切换场景或改变原图字典顺序不会改变编号。

这些数据方便之后转换 STM32 地图表，本轮没有生成固件或改动 STM32 工程。

## 本次修正：单出口环路与丢失目标后折返（2026-10-04）

截图中的 N008、N009、N018、N019、N028 这一圈只有 N027 通向外部。原算法把圈内两个行驶方向误当作两条逃生出口。现在从现有图识别只有一个外部入口、内部无分岔的环路，排除其内部藏点；N027 也不作为藏点，因为去掉圈内方向后只剩一条外部退路。预设路线卡随候选藏点重新生成。道路和节点编号不变。

警方实际检出圈内目标且自身在圈外时，用检测位置比较双方到出口的最快时间（包括警方转向成本，并保守修正检测点距网格节点的偏移）。能够抢先或同时到口才改去堵出口；来不及则继续追踪。到口短时守候，满 2 秒后的决策释放堵口任务，4 秒内不重复同一堵口；最后检出超过 12 秒或新检测表明目标已离开、已赶不及堵截时取消。只使用有限观测，不能读取未检测对手真值。堵口行为由定点测试验证，本次七局不代表已演示成功堵口抓捕。
