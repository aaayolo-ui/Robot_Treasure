# 16D 实际C策略回放

打开 [回放](http://127.0.0.1:8765/variants/16d/replay.html)。原 `../../replay.html` 保留，本目录不修改旧回放或16D固件。

小偷的规划及3/5稳定帧、地图投影、场界门控直接执行ARMCC编译的16D C代码。编译输入哈希保存在report.json，可与固件源码核对。CPU模拟器只用于电脑生成回放，STM32运行不依赖它或服务器。

道路运动、转向/换向等待与连续接触裁定复用原Python仿真；警方沿用现有有限检测追踪/局部排查策略。没有将全局对手真值传给C规划器：真值只用于生成虚拟激光读数、显示和接触裁定。小偷移动期关闭检测，停稳80ms后按20ms周期送入虚拟测距；5%漏帧和理想测距只是仿真假设，不包含实物脚、人、灰度误识别、安装偏移、串口电气与真实计算超时。

## 四场各一局，种子7

| 场景 | 结果 | 持续时间 |
|---|---|---:|
| 完整开局、双方同速 | 取宝后被抓 | 17.760209秒 |
| 完整开局、警方快20% | 取宝后被抓 | 15.889841秒 |
| N023藏点专项：已持宝、警方从N031接近 | 无安全首段，停止后被抓 | 0.178042秒 |
| N059藏点专项：已持宝、警方从N075接近 | N059→N063→N044，之后无安全首段并被抓 | 13.888807秒 |

专项场景的起点和持宝状态明确指定，不能当作完整比赛的胜率。没有加入警方较慢、故意停等或全局观测场景。

## 暴露的问题

N023虽然有环路退路，但从该点沿北、东、南的连续直线视距都只有约300mm；600mm量程不等于隔着拐角提前发现来车。当前藏点质量没有充分结合检测提前量、稳定确认延迟、启动耗时与接触距离。检测确认时，16D的保守最早可达时间筛选已拒绝首段，返回 `ESCAPE_PLAN_FAILED`，仿真忠实保留停车行为。

N059专项能发生两次转移，但N044再次遇到近距目标时仍进入故障。当前版本还不能据此声称避逃策略成熟。后续应优化藏点可检测视距、紧急撤离与保守风险模型；本轮为了让结果可复核，没有修改16D让它看上去更成功。

## 观看

节点编号默认显示；两车使用蓝色实线与橙色虚线。可播放、拖动时间轴、切换速度和场景，使用“跳到首次藏匿”“跳到检测决策”“跳到抓捕时刻”。页面显示实际C决策的目标、状态展开数、威胁数、时间余量与退化选择。停止故障单独标注。

离线检查通过：C源码哈希一致、指定取宝前缀、88节点/106路段、移动期不启用激光、接触即终止、C返回路线及决策字段。页面内两个JavaScript脚本语法检查通过，本地HTTP返回200。浏览器自动交互检查被URL安全策略拒绝，没有绕过限制，也不宣称点击和播放已完成浏览器实测。
