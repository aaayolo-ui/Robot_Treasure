# 密室夺宝比赛规则整理

> 本文面向 Robot_Treasure 机器人的机械、电控和软件研发，用于快速定位比赛约束并指导方案设计。规则内容依据《2025 江苏省大学生机器人大赛密室夺宝项目竞赛规则 V2.0》提炼；项目最终参赛要求应以组委会最新发布的正式规则、补充通知及现场说明为准。

## 1. 项目简介

本项目对应 **2025 江苏省大学生机器人大赛“密室夺宝”项目**。比赛由两台自主机器人进行对抗，双方角色分别为：

- **警方机器人**：寻找并保护宝藏；如果宝藏已被小偷获取，则实施抓捕。
- **小偷机器人**：争取先于警方获取宝藏，并携带宝藏逃脱警方抓捕。

因此，机器人不仅需要完成迷宫循迹和宝藏获取，还需要根据本方角色、宝藏状态及对手机器人的位置执行不同策略。

## 2. 比赛任务

单局比赛的核心任务链如下：

```text
开始比赛
    ↓
机器人自主运行
    ↓
寻找宝藏区域
    ↓
获取宝藏
    ↓
持续触发声光提示
    ↓
警方完成抓捕 / 小偷保持未被抓捕直至比赛结束
```

研发时可将任务拆分为六个状态：启动、循迹导航、宝藏区搜索、宝藏获取确认、声光提示、抓捕或逃脱。声光提示必须由“确认已获取宝藏”这一条件触发，不能仅凭机器人进入宝藏区触发。

## 3. 比赛流程

| 阶段 | 规则要求 | 研发关注点 |
|---|---|---|
| 赛制 | 三局两胜制 | 至少赢得两局才能赢得整场比赛 |
| 角色 | 双方角色轮换 | 同一机器人应支持警方与小偷两套策略，或支持赛前切换角色配置 |
| 单局开始 | 机器人按比赛要求启动后自主运行 | 启动后不得依赖遥控或人工干预 |
| 单局进行 | 每局限时 3 分钟 | 导航、取宝及对抗策略必须在时间限制内完成 |
| 单局结束 | 根据宝藏获取、抓捕和超时状态判定胜负 | 软件应可靠保存“是否取宝”和“当前角色”等关键状态 |

## 4. 场地规则

| 项目 | 要求 |
|---|---|
| 场地尺寸 | 3.6 m × 3 m |
| 车道宽度 | 0.3 m |
| 黑线宽度 | 25 mm |
| 比赛地图 | 迷宫地图 |
| 宝藏位置 | 宝藏区中心 |

工程上，机器人应围绕 25 mm 黑线完成循迹与路口识别；底盘外形和转弯能力需要适应 0.3 m 宽车道。宝藏获取机构应能在机器人到达宝藏区中心附近时可靠工作。

## 5. 宝藏获取规则

- 宝藏为**铁块**，获取机构必须能够可靠吸附、夹持或承载该物体。
- 机器人必须具备**宝藏检测功能**，不能只用固定延时推定获取成功。
- 机器人确认获取宝藏后，必须持续进行**声、光提示**。
- 未获取宝藏时禁止提前发出代表取宝成功的声光提示。

对应的软件触发关系应为：

```text
获取机构动作 → 宝藏传感器确认 → 锁存“已获取”状态 → 持续开启 LED 和蜂鸣器
```

传感器未确认时，不应进入“已获取”状态。具体检测传感器及阈值需要通过实物铁块测试确定。

## 6. 胜负判定

### 6.1 警方胜利

- 警方先获取宝藏；或
- 小偷已携带宝藏时，警方完成对小偷的抓捕。

### 6.2 小偷胜利

- 小偷获取宝藏；并且
- 在本局比赛时间内未被警方抓捕。

### 6.3 平局

- 比赛结束时双方均未获取宝藏。

工程实现中，角色不同会改变取宝后的目标：警方取宝后以保护宝藏为主；小偷取宝后则需要在余下时间内持续规避警方。

## 7. 机器人设计限制

| 规则 | 设计影响 |
|---|---|
| 尺寸限制 ≤ 0.28 m³ | 限制底盘及全部安装结构的总体空间，设计完成后需按官方检录口径复核 |
| 必须自主运行 | 不能遥控；启动、导航、取宝、提示及对抗决策均需在机器人端完成 |
| 沿黑线循迹 | 需要灰度传感器，并针对 25 mm 黑线完成安装间距、阈值及控制参数标定 |
| 获取铁块宝藏 | 需要取宝机械结构，同时需要检测宝藏是否真正获取 |
| 获取后持续声光提示 | 需要 LED、蜂鸣器及可锁存的取宝状态逻辑 |
| 安装机器人识别结构 | 需要预留识别板的安装位置，保证结构稳固且符合规则要求 |
| 车道宽度 0.3 m | 底盘宽度、转弯轨迹和外伸机构应避免超出可行驶空间 |
| 单局限时 3 分钟 | 路径规划、行驶速度和异常恢复策略需要满足时间约束 |

> “设计影响”是从规则推导出的工程要求，不是新增竞赛规则。尺寸和识别结构应在制作、检录前再次对照当届正式文件确认测量方式及安装细节。

## 8. 当前 Robot_Treasure 方案对应

| 规则要求 | 当前对应设计 | 状态与验证重点 |
|---|---|---|
| 25 mm 黑线循迹 | 12 路灰度传感器 + 循迹 PID | 已确定方案；需在正式赛道材质上标定阈值和安装高度 |
| 迷宫导航 | 路口识别 + 路线判断 | 软件框架已规划；需覆盖岔路、丢线和转弯恢复 |
| 获取铁块宝藏 | 磁吸机构 | 已确定方案；需验证吸力、对位容差及行驶中防脱落能力 |
| 必须检测宝藏 | 宝藏检测功能待选型 | 规则要求已明确；当前方案仅描述延时吸取，需补充独立的获取确认手段 |
| 获取后持续声光提示 | 高亮 LED + 蜂鸣器 | 已确定方案；应由宝藏检测结果触发并保持至本局结束 |
| 自主运行 | STM32 主控 + 机器人状态机 | 已确定总体方向；需实现警方/小偷角色配置及全过程自主控制 |
| 对手机器人检测 | 前、后、左、右四方向 ToF 测距候选方案（当前 1 个 AI-1811 待测试；普通红外备用/对比） | 项目方案选型；需验证黑色 ABS 检测、距离/角度、运动目标、环境光及多模块通信，再决定是否扩展到四方向 |
| 适应尺寸及车道限制 | 四轮普通轮差速底盘 | 已确定方案；结构定型后需实测外形、转弯包络和 0.3 m 车道通过性 |
| 机器人识别结构 | 预留识别板安装位 | 尚未在现有总体方案中落实，机械设计阶段需补充 |

上述传感器、机构和底盘是 **Robot_Treasure 当前工程方案**，并非官方规则指定的唯一实现方式。
