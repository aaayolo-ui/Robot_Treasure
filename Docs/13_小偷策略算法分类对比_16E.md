# 小偷策略算法分类、对比与 16E 选择

2026-10-12。16D 工程和回放保留。本次新建
`STM32/Keil_Project/Thief16E_VisibilityEscape_FourLaser_Test`，使用相同地图、取宝路线、运动参数和四方向激光接口。

当前选用的改动解决了“保守风险估计没有安全方案就停车”的问题，并缩短了近距目标的确认等待。下面的对比还没有得到可稳定获胜的策略。

## 算法分类与适用条件

| 类别 | 可以借鉴什么 | 对本项目的判断 | 本次处理 |
| --- | --- | --- | --- |
| 静态图搜索，A*/Dijkstra、朝向状态格 | 在预存地图上求有方向、有前进/倒车模式的时间代价路线 | 88 节点可做固定数组搜索；只找短路不能充分处理交会和藏点暴露 | 沿用 16D 的 704 状态搜索，不整套移植 [SBPL](https://github.com/sbpl/sbpl) |
| 时间规划，SIPP | 比较到达同一位置的时刻，同时检查边上的交会 | 原论文使用预测动态障碍轨迹，并有运动假设；这里只有有限的激光线索，不能照搬其保证 | 保留路段、转向、换向耗时和沿边风险采样的思想；本实现不是完整 [SIPP](https://www.cs.cmu.edu/afs/cs/Web/People/maxim/files/sipp_icra11.pdf) |
| 考虑动力学的时间规划 | 不把停车、加速和转向视为瞬时动作 | 本车的动作代价来自旧标定的估计，尚不构成完整动力学模型 | 作为后续标定方向，未声称实现 [SIPP with kinodynamic constraints](https://arxiv.org/abs/2302.00776) |
| 有限可见的追逃、信息区域搜索 | 维护对手可能的位置，利用断开视线和搜索分支 | 与“藏好—检测到来车—转移—再藏”的需求匹配 | 沿用近期地图内观测与可达区域估计；警方保持原有限检测策略作对照，未移植完整信息空间求解器。[LaValle](https://msl.cs.uiuc.edu/planning/node631.html) |
| Minimax 图博弈、离线策略表 | 比较对手多种走法，在最坏情形下选动作；离线结果可以压缩成表 | [有限可见追逃研究](https://re.public.polimi.it/handle/11311/1099128)包含只在见到追捕者后离开藏点的模型，但完整博弈求解不等于当前的路径搜索 | 本次采用“最小保守余量优先”的有界启发式比较；没有宣称实现论文的完整 minimax 或最优博弈解 |
| ORCA/RVO2 避碰 | 连续速度空间中的局部避碰 | 其相互避碰假设与主动追捕有差别，车还受到黑线路网限制 | 暂不采用。[ORCA](https://gamma.cs.unc.edu/ORCA/)、[官方 RVO2](https://github.com/snape/RVO2) |
| 部分可观测强化学习、GNN | 学习复杂的追捕与信息保留策略 | [R2PS](https://proceedings.iclr.cc/paper_files/paper/2026/hash/311207bb626e36a8f1d3eb92aa67af22-Abstract-Conference.html)是值得研究的方向；本项目没有可直接验证的训练模型和 MCU 推理资源结果 | 本次不加入训练/推理依赖，不据此承诺 STM32 能运行 |

“适合本项目”的判断是依据现有地图、传感器和控制接口做的工程判断，不是上述论文对本车性能的结论。

## 已确认的原因与实际修改

1. 16D 在逃跑首段的保守时间余量 `<=0` 时直接删掉该首段；所有首段被删后，应用进入 `ESCAPE_PLAN_FAILED` 并停车。16E 保留道路连接、身体轴线和禁止朝已见目标驶去的约束；没有正余量方案时，选择保守余量较好的可走方案，日志明确标为 `DEGRADED=1`。它仍可能被抓，不能称为保证安全。
2. 普通目标继续使用 5 帧窗口内 3 帧有效、距离变化不超过 120 mm 的确认；距离不超过 400 mm、置信度至少 20 时，允许同一通道连续 2 帧有效，且当前窗口内有效距离变化不超过 80 mm 的目标较快触发。低置信度、无道路投影、超出场界和移动期返回都不能绕过门控。20 ms 是仿真的采样周期；实车等待取决于模块的实际帧率。
3. 暴露藏点和前一个藏点仍被优先避开；如果没有新藏点可用，允许应急重用，而不是仅因冷却限制停车。日志增加 `REUSED=1`。来车方向封住身体轴线两端、地图/朝向错误等情况仍不盲目启动。激光距离不是已标定的两车中心距离，不用它直接认定捕获并停车；仿真的接触裁判独立判断中心距离。
4. 单纯藏点预警评分、额外的警方转弯下界、扩大到长轴十字路口和固定远处初始藏点均做了独立试验，默认不启用。保留比较脚本和数据，方便复核。

默认开关位于新工程的 `Algorithm/ThiefStrategy/ThiefStrategyConfig.h`：

| 参数 | 默认值 | 含义 |
| --- | --- | --- |
| `THIEF_EMERGENCY_ESCAPE` | 1 | 负的保守余量不再直接造成停车；冷却藏点可作最后的选择 |
| `THIEF_FAST_NEAR_CONFIRM` | 1 | 地图内近距高质量目标的连续两帧确认 |
| `THIEF_REACTION_HIDE_SCORE` | 0 | 预警时间藏点评分；试验没有稳定收益 |
| `THIEF_TURN_REACH_MODEL` | 0 | 带朝向的警方转弯时间假设；没有增加收益且警方下界未实测 |
| `THIEF_BRANCH_JUNCTION_HIDES` | 0 | 扩大到某些长轴十字路口；未作为默认藏点 |
| `THIEF_INITIAL_HIDE_NODE` | 0 | 仍按合法藏点评分选开局藏点，没有硬编码远处目标 |

## 同条件比较

比较调用 ARMCC 5 编译的真实 C 规划器和激光门控，通过 Cortex-M3 CPU 模拟器执行。小偷没有接收全局警方坐标。只有虚拟传感器产生距离样本；警方在所有版本中使用相同的两格有限检测、追击与区域搜索策略。

共同条件：300 mm 格距；前进 674 mm/s、倒车 679 mm/s 的估计；转向额外耗时 768 ms、前进切倒车 282 ms、倒车切前进 274 ms；两格 600 mm 检测；20 ms 周期、5% 漏帧；双方中心距离达到 180 mm 即判警方获胜。双方共用一辆车的参考标定，警方另测同速和快 20%，没有人为减慢警方。

开发筛选种子为 7、8、9。下表为完整开局的平均生存时间，单位秒，数值不是胜率：

| 候选 | 同速 | 警方快 20% | 结论 |
| --- | ---: | ---: | --- |
| 16D 原版 | 17.760 | 15.890 | 对照；检测后因风险筛选停车 |
| 应急可走路线 | 37.821 | 26.948 | 收益主要来自这项修复，保留 |
| 上项 + 近距快速确认 | 37.838 | 26.948 | 近距确认更快；对这些终局的收益很小，保留并继续测噪声 |
| 上项 + 预警评分权重 40 | 37.838 | 26.948 | 无新增收益，默认关闭 |
| 上项 + 预警评分权重 64 | 25.719 | 20.237 | 更差，默认关闭 |
| 上项 + 警方转弯可达模型 | 37.838 | 26.948 | 无新增收益，默认关闭 |
| 固定 N039 初始藏点 | 25.719 | 20.237 | 比保留方案差 |
| 固定 N044 初始藏点 | 10.817 | 10.207 | 去藏点期间相遇，拒绝 |
| 固定 N059 初始藏点 | 12.062 | 61.321 | 对速度关系敏感，拒绝作为固定开局 |
| 固定 N062 初始藏点 | 12.062 | 72.300 | 快警方一例好，但同速时提前相遇，拒绝作为固定开局 |
| 固定 N063 初始藏点 | 12.062 | 34.461 | 同速时提前相遇，拒绝作为固定开局 |

还单独筛选了 N011、N038、N076 十字路口，种子只有 7。N038 为 31.975/24.011 秒；N076 在快警方场景有 74.329 秒，但同速仅 12.062 秒；均不作为默认。不能拿一个快警方的长生存场景抵消另一场直接相遇的风险。

开发数据分别在新回放目录中的 `strategy_comparison.json`、`turn_reach_comparison.json`、`hide_candidate_comparison.json`、`junction_candidate_comparison.json`。它们是开发阶段快照，带当时的源文件哈希；最终方案另以终版源码复核，不把阶段快照伪装成终版数据。

## 未参与筛选的种子复核

种子 10、11、12、13、14，每个版本分别运行两种完整开局和两种藏点专项，共 40 次。专项从指定藏点开始并直接持有宝藏，与完整比赛分开计分。

| 场景 | 16D 平均生存时间 | 16E 平均生存时间 | 16D 规划停车次数 | 16E 规划停车次数 |
| --- | ---: | ---: | ---: | ---: |
| 完整开局，双方同速 | 17.760 s | 37.832 s | 5 | 0 |
| 完整开局，警方快 20% | 15.890 s | 26.948 s | 5 | 0 |
| N023 近距来车专项 | 0.178 s | 0.623 s | 5 | 0 |
| N059 侧方来车专项 | 13.161 s | 14.334 s | 5 | 0 |

复核中两版小偷获胜数均为 0。新方案修好了这一组场景的规划停车，并延长了生存时间，仍然不是可靠获胜策略。结果见 `heldout_comparison.json`。随机种子主要改变漏帧，在部分场景中结果相同；这些复核没有覆盖所有对手策略和启动误差。

## 回放和工程边界

- 新回放：`http://127.0.0.1:8765/variants/16e/replay.html`，节点标注默认显示，保留路段点击、标注开关与地图 JSON 导出。两车轨迹仍分别为蓝色实线、橙色虚线。
- 到宝藏的指定路线保持 `N054→N053→N044→N036→N035→N034→N033→N025→N015→N006→N005→N004`。宝藏点 N005 在直段中，不停车，不把它当成可识别路口。
- 默认合法藏点仍为 N023、N039、N044、N059、N062、N063；死路、单入口回环及中途伪造的“节点”不作为默认藏点。初始选到 N023。近距背后追来时，这个藏点仍可能缺少反应时间。
- 行驶期激光接收仍关闭，停稳后启用，继承原工程对电机/串口资源的安排。因此逃跑路线上出现新来车时不能实时反应，这是当前接口的一项重要限制。
- 定位仍依赖预存路段、编码器和灰度路口；原路口距离容差较宽，定位正确并未由本次仿真证明。激光能筛掉地图外或无道路投影的物体，不能仅凭距离证明地图内物体一定是警方。
- 仿真假设理想定位、理想循迹、估计动作等待与中心接触阈值，不模拟完整惯性、轮胎打滑、车体尺寸、传感器安装偏移、串口电气或真实 MCU 中断。规划余量不等于物理防撞保证。
- Keil 全量编译：0 Error(s), 0 Warning(s)。Flash 43,796 B，RAM 34,368 B，目标容量为 256 KiB Flash/48 KiB RAM。算法工作区 13,265 B、2,048 B 栈均已计入 RAM。静态调用图已知最大栈 704 B，还存在未知调用/中断项，不能视为硬件栈安全证明。100 ms 规划预算保留，板上 `COMPUTE_MS` 尚未实测。
- 无需虚拟机或远程服务器。固件在 STM32 本机执行；电脑上可选的本地 HTTP 服务只用于观看回放。

**仅编译通过，尚未完成硬件验证**。实际 C 算法测试、仿真对比和图像检查已经执行；没有烧录、驱动车辆、提交或推送。

完整文件清单和相对 16D 的源码差异见新工程 `FILE_MANIFEST.md`、`SOURCE_CHANGES.json`、`SOURCE_DIFF.patch`，回放目录另有文件清单。16D 的 171 个源文件/配置快照校验通过。
