# 小偷单前向激光定位与逃跑策略

更新日期：2026-10-10。

本文从现有二维对抗策略中提取小偷部分，并收敛到当前实车条件：地图预先写入 STM32、只有一只朝前的 AI-1811 激光测距模块、小车能够维护自身地图位置。独立实验工程位于
`STM32/Keil_Project/Thief16A_FrontLaser_MapStrategy_Test`。当前已完成代码、离线路线验证及 ARMCC5 全量构建（0 错误、0 警告），尚未完成实车验证，也不表示单点激光具备目标身份识别能力。

## 当前实现与后续设计的边界

下文包含目标设计，实际已实现范围以工程 README 为准：首藏点固定为 N059；藏点停稳后才启用 50～600 mm、连续道路与场界及 3/5 稳定帧过滤；逃跑首段强制反向倒车，后续目标按候选表与距离约束选择。当前尚未实现相遇时间优化、行驶中激光避碰、定位可信度与自动重定位。安装偏移及场界误差待实测，TFT 在停止或底盘允许暂停时刷新。

## 1. 已知场地与坐标约定

- 场地长 3.6 m、宽 3.0 m，相邻黑线中心距 0.3 m。
- 当前地图为 12×10 个黑线网格位置，图坐标 x 向右、y 向下。
- `Tools/TreasurePursuitSimulator/map_annotations.json` 使用黑线中心为基准的坐标：N001 为 `(0, 0)`，小偷出生点 N054 为 `(3.3, 1.5) m`，警方出生点 N081 为 `(0, 2.7) m`，宝藏点 N005 为 `(1.65, 0) m`。
- 在“最外侧黑线距离场地边缘半格”的设计假设下，地图坐标中的场地边界为：

  ```text
  -0.15 m <= x <= 3.45 m
  -0.15 m <= y <= 2.85 m
  ```

  等价的场地边缘坐标为 `X = x + 0.15 m`、`Y = y + 0.15 m`，范围分别为 `0～3.6 m` 和 `0～3.0 m`。外侧黑线到场地边缘的 0.15 m 必须现场量一次；若实物不是这个间距，边界常量必须按实测值修改。

小车不只保存一个 `(x,y)` 浮点数，而应保存下面的定位状态：

```text
当前节点 node_id
当前路段 edge_from -> edge_to
路段进度 progress_mm
车头方向 heading = N/E/S/W
连续地图坐标 x_mm, y_mm
定位可信度 pose_confidence
```

开机时由已知出生点和摆放朝向初始化。经过预期路口后，把 `node_id` 更新为路线表中的下一节点；两节点之间用编码器里程估计 `progress_mm`，航向由路线方向与姿态传感器共同校验。相同形状的路口不能单独确定全局坐标，所以路口灰度特征只用于确认“到达预期节点”，不能让程序在多个相同路口之间任意跳转。若实际路口特征与预期不符，应降低定位可信度，在下一安全节点停车或进入重定位流程，不能继续用错误坐标过滤激光数据。

## 2. 前激光数据先投影到地图

AI-1811 只给出车头前方一个距离值和可信度，不能直接给出“这是警车”。设小车中心坐标为 `Pcar=(x,y)`，车头单位向量为 `d`，激光安装点相对车中心的前向偏移为 `offset`，测得距离为 `r`，则候选物体位置为：

```text
Psensor = Pcar + offset * d
Phit    = Psensor + r * d
```

`offset` 必须按安装完成后的实物测量。若传感器没有完全对准车身中心线，还要把实测安装偏角加入方向变换。

当前策略只使用两格范围，即最大 0.6 m。传感器能够报出更远距离，不等于策略必须采用更远目标。0.6 m 小于场地外 1 m 警戒距离，有利于排除警戒带外人员，但边界投影仍然必须保留，因为队长可能在警戒带内，人体也可能伸入光路。

## 3. 把测距分成三层，不把物体直接当警方

### 3.1 原始有效帧

先检查 8 字节帧头、校验和、距离范围和 `CONF`。校验正确只说明串口帧完整，不说明目标是警方。`CONF` 的策略阈值应根据现场对车壳、地面、鞋和裤腿的测量结果确定，不能从协议最低有效值直接推导。

### 3.2 地图内道路候选

只有同时满足以下条件，才把读数升级为“地图内道路上的物体候选”：

1. `r` 不超过 0.6 m，并通过多帧稳定性检查。
2. 当前定位可信度足够高。
3. `Phit` 落在 3.6 m×3.0 m 场地边界内，且误差区间没有完全落到场外。
4. 从当前车位沿车头方向确实存在相连的前向黑线路段；射线不能越过道路终点、断路或场地边界后再命中目标。
5. `Phit` 到这条可见前向道路中心线的距离小于“半个对方车宽 + 定位误差 + 测距误差”。对方车宽尚未录入，因此该门限必须实测后填写，不能先猜一个固定值。

实现时应从当前路段沿车头方向在地图图结构上做一次短距离射线检查，而不是只判断 `Phit` 是否靠近全图任意黑线。否则场外人员可能恰好与远处另一条道路共线而被误收。

建议初始时采用“最近 5 帧中至少 3 帧通过，且中位数距离稳定”的确认方式。AI-1811 主动上报周期约 20 ms 时，这相当于约 0.1 s 的确认窗口；最终帧数需结合实测漏帧和车辆速度调整。

### 3.3 对手线索

单只前向激光不能区分警车、人员、固定物和场内其他障碍。因此程序内部应把结果命名为 `front_road_obstacle` 或“前方道路物体候选”，不要命名为 `police_detected`。只有比赛环境保证道路上不会出现其他物体时，策略层才可把持续的地图内道路候选当作警方线索。

被判为场外、离开合法前向道路或不稳定的读数，不更新警方位置，不触发换藏点。非常近的物体仍可触发底盘安全停车，但安全停车不能写入“警方已出现”的地图记忆。

## 4. 场外人员过滤

按照下面的顺序过滤，优先级高于逃跑决策：

1. **没有合法前向道路就不建立警方线索。** 例如位于外侧死路端点且车头朝场外时，前方读数一定不来自合法道路上的车。
2. **射线先碰到场地边界时拒绝后方读数。** 计算车头射线到场地边界的距离 `r_edge`；若物体误差区间位于 `r_edge` 之外，判为 `OUT_OF_FIELD`。
3. **只接受当前连通道路走廊。** 射线经过断路、端帽或没有黑线的空白区后得到的读数判为 `OFF_ROAD`。
4. **限制策略距离为 0.6 m。** 警戒带在场地边缘外 1 m，正常站在警戒带外的人员不会进入两格策略距离。
5. **连续帧确认。** 单帧闪烁、低可信度和大幅跳变只保留为诊断数据。

边界判断必须包含以下总误差：

```text
boundary_error = 定位误差 + 激光测距误差 + 安装偏移误差 + 车身循迹横向误差
```

若 `pose_confidence` 过低，程序不能武断地说目标在场外。此时应保持黑线循迹优先，降低策略速度，并在下一已知节点校正位置。只靠一只测距激光无法从物体外观识别“人还是车”，因此上述方法能大幅减少场外误检，但不能保证所有人体目标都被排除；如果人员或肢体进入场地内部的合法道路投影，仍可能被当成道路物体候选。

## 5. 距离如何决定动作

距离不能直接映射成“左转”或“右转”。程序应先计算两项时间：

```text
t_contact  = (r - 接触距离 - 测距误差余量) / (小偷当前速度 + 警方假设最大迎面速度)
t_escape   = 到下一决策节点的时间 + 转向或换向时间 + 控制余量
```

同时根据实车标定建立停车距离：

```text
d_stop(v) = 响应阶段滑行距离 + 制动距离 + 定位/测距安全余量
```

在没有测出减速度之前，不用理论值假装精确；应在不同速度下实测，保存为查表数据。动作规则如下：

| 条件 | 动作 |
| --- | --- |
| 读数未通过地图门控 | 不改变对手线索和藏匿路线；过近时只做底盘安全停车 |
| `r > 0.6 m` | 不进入当前两格策略 |
| `r <= d_stop(v)` | 立即制动；若刚走过的路段仍合法且能够远离测得物体，沿原路受控后退到上一个安全节点 |
| `r > d_stop(v)` 且 `t_escape` 明显小于 `t_contact` | 执行到下一决策节点并转入风险最低的出口 |
| `t_escape` 不小于 `t_contact` | 不继续朝物体靠近，优先制动或沿刚走过的合法路段撤回 |

这里的“原路撤回”不是盲目长距离倒车。当前只有前激光，倒车方向没有测距覆盖，因此只允许沿刚刚确认走通的路段，以低风险动作回到上一个地图节点；倒车距离和完成条件仍由路线状态、后向循迹灰度和节点识别控制。

在下一节点选择出口时，先删除朝向 `Phit` 的道路，再比较各候选路线与物体可能到达区域的最早交会时间。优先选择交会时间最晚、出口多、没有死路或单出口口袋、不会立刻进入长直道的路线。这样距离决定“是否来得及到路口”，地图决定“到路口后走哪边”。

## 6. 小偷状态机

```text
START_TO_TREASURE -> SEEK_HIDE -> HIDE -> ESCAPE -> SEEK_HIDE
                              \-> LOCALIZATION_RECOVERY
```

### 6.1 取宝

从 N054 按包含实测直行、转弯和换向耗时的最短时间路线前往 N005。经过宝藏点即取宝，不减速、不停车。途中出现确认的前方道路物体时，禁止继续沿同一前向走廊迎上去，在下一可执行节点选择替代路线；若距离已进入底盘安全阈值，则先停车避碰。

### 6.2 选择藏点

藏点只选地图节点，且同时满足：

- 不是死路端点，也不在只有一个外部出口的封闭环路内。
- 至少有两个可用撤离方向。
- 不在长直道中间；沿所在直道的可见跨度原则上不超过三格。
- 到达路线不穿过最新的前方道路物体走廊及其可能到达区域。
- 优先需要警方多次转弯才能看见、附近分岔较多、能转移到另一个合格藏点的位置。
- 降低刚暴露藏点和刚走过路段的评分，避免短时间折返。

评分顺序为：预计最早相遇时间裕量、出口数量、警方预计搜索耗时、路线动作耗时、重复路段代价。距离最远不是唯一目标。

### 6.3 藏匿

到藏点后停车，把前激光朝向“警方最可能进入的道路”，并确保另一条撤离边不需要从测得物体方向穿过。只有一只前激光时无法同时观察侧后方，所以应优先选择主要来路明确、但仍有两条撤离路径的节点；不能假设四方向都已检测。

没有确认的地图内道路候选时保持停车，不做所谓连续智能游走。被拒绝的场外读数只在 TFT/日志显示拒绝原因，不改变藏点。

### 6.4 逃跑

藏匿时确认前方道路物体后，以投影点 `Phit` 为最后线索：

1. 暂时禁用当前藏点和面向物体的首段道路。
2. 在图上扩张物体可能到达区域；扩张距离包含检测延迟、转向时间和警方最大假设速度。
3. 从其他出口中选择最晚与该区域相交的路线，目标是下一个合格藏点。
4. 前几段优先离开物体所在半平面，但必须服从实际道路连通关系。
5. 路线确定后执行到下一个决策节点；只有新的确认读数或即将碰撞才提前重规划，避免在同一路段左右来回。

前激光只能说明物体位于车头射线上，不能知道对方朝向和速度。因此逃跑计算要使用一个可能位置区间，而不是把单次距离当成精确的警方二维轨迹。

## 7. 固件模块边界

```text
AI1811 parser
  -> RangeObservation { distance_mm, confidence, timestamp }
  -> PoseTracker { node, edge, progress, heading, x_mm, y_mm, confidence }
  -> MapRayGate { accepted, hit_x_mm, hit_y_mm, reject_reason }
  -> ThiefStrategy { state, next_node, route, hide_facing }
  -> RouteExecutor / line follower
  -> chassis control
```

推荐为 TFT 和串口日志保留以下字段，方便现场确认过滤是否正确：

```text
POS N054 E x=3300 y=1500 q=HIGH
LASER r=428 conf=xx RAW_OK
GATE ROAD_OK hit=(2872,1500)
ACTION TURN_AT_NEXT_NODE margin=xxxms
STATE HIDE -> ESCAPE goal=Nxxx
```

拒绝时显示 `OUT_OF_FIELD`、`NO_FORWARD_ROAD`、`OFF_ROAD`、`UNSTABLE` 或 `POSE_LOW`，这样可以区分“传感器看到了东西”和“策略接受了警方线索”。

## 8. 落地验证顺序

1. 电机不运行，验证 AI-1811 距离、可信度、帧率和 TFT 显示。
2. 手推小车经过已知节点，核对 `node_id`、朝向和连续坐标，不接入逃跑控制。
3. 用纸板分别放在合法道路、无路空白区、场地边界外，核对 `ROAD_OK`、`OFF_ROAD` 和 `OUT_OF_FIELD`。
4. 在最外侧道路上分别让车头平行边界和朝向场外，验证地图射线门控。
5. 单车低速执行“取宝—藏点—检测纸板—下一藏点”，确认不会因拒绝读数改路线。
6. 最后才用两辆车验证检测、逃跑和接触判定。
