# 夺宝对抗策略说明：小偷与警察

本文用自然语言说明当前电脑仿真中的策略，供讨论比赛思路和后续移植使用。依据为 `Tools/TreasurePursuitSimulator/simulate.py`、`config.json` 及配套说明，整理日期为 2026-10-04。

## 一、双方共同遵守的前提

- 双方提前保存地图，可以利用道路连接、路口位置和路段长度规划路线。知道地图不等于知道对方在哪里。
- 决策使用自身位置、有限范围内的检测结果、最近检测记录和地图先验。回放显示双方位置只是为了复盘，不代表小车拥有全局观测。
- 当前仿真假设自身位置已知，检测范围内的对方位置能够测得。实际红外传感器能否提供这样的信息、能否确认目标就是对方小车，仍需另外验证。
- 选择路线时同时计算直行和转向耗时，不只比较路程。90°转弯与前后退换向目前都设为 0.5 秒；后退不等于车身旋转 180°。
- 经过宝藏中心即可取宝，不减速、不停车。
- “立即追踪”或“立即逃跑”表示检测后立即改变决策优先级。已经开始的转向需要完成，沿线行驶通常到下一地图节点再执行新路线。

| 参数 | 当前仿真设置 |
| --- | --- |
| 常规双方直行速度 | 都为 1.95 米/秒 |
| 警方较快对照 | 警方为小偷速度的 1.2 倍 |
| 警方检测距离 | 所有当前场景均为三格，即 0.9 米 |
| 小偷检测距离 | 按场景为两格或三格，即 0.6 或 0.9 米 |
| 检测模型 | 四方向窄角检测，每 20 毫秒检测一次，设有 5% 漏检概率 |
| 接触判定 | 双方中心距离达到 0.18 米以内即判抓捕 |
| 比赛时限 | 180 秒 |

这些数值是当前模型参数，不是实车测量结论。道路长度沿用地图的 0.3 米格距，尚未实地标定。

## 二、小偷策略

### 1. 开局先取宝，遇到警方先避险

正常情况下，从出生点选择预计耗时最短的路线赶到宝藏。若途中检测到警方，逃避优先，不为了坚持取宝路线而继续迎面接近。威胁解除后再继续任务。

### 2. 取宝后选择有退路的藏点

藏点放在地图中真实存在的拐角或路口，不放在普通直道路段中间。选择时综合考虑以下条件：

- 不在死路中停靠，也不选择只有一个口连接外界的封闭环路。
- 所在整条直道跨度不超过三格，避免在长直道上等待高速接近的警方。
- 至少保留两个合适的环路方向，且不能把进入单出口封闭环路的方向当成可靠退路。
- 尽量远离警方预计的取宝来路，优先考虑需要警方绕行或多次转弯才能探测到的位置。
- 附近分岔较多，方便转移到下一个藏点；同时考虑到达该点的时间和沿途风险。
- 降低反复经过旧路线、频繁回到刚暴露藏点的倾向。

例如，右上角 N008、N009、N018、N019、N028 组成的一圈，只有 N027 通向外部。圈内虽然能向两个方向走，最后仍必须经过同一个出口，所以这些内部节点不再作为藏点；N027 本身也不作为藏点。

这里的“最佳藏点”是当前信息下评分较好的候选点，尚未证明是全局最优。没有近期检测时，对警方来路的判断只是地图先验。

### 3. 到藏点后等待，有检测再撤离

到达藏点后，先把朝向准备到有利于离开的方向，再保持停靠。没有检出警方时，不因为回放中警方位置变化而主动离开。

实际检出警方后进入逃跑流程。已经停靠且暴露的藏点暂时禁用 30 秒，避免刚逃走又立即返回。前往藏点途中遇到警方，则先评估当前路线是否仍然安全。

### 4. 逃跑要远离警方的来路，并检查是否会相撞

检测到右侧有警方时，优先考虑向左侧区块转移；其他方向同理。但不能只按左右方向机械转弯，还必须检查道路是否相通、转向是否来得及，以及警方能否更早到达前方交会点。

选择逃跑路线时，先比较近期接触风险，再考虑以下因素：

1. 离开后的前几段是否会靠近警方，或进入警方赶来追自己的通道。
2. 是否向远离警方的区块转移。
3. 下一藏点是否容易被警方直接探测到。
4. 到达下一藏点需要多少时间，途中有没有可用分岔，是否重复刚走过的路线。

允许直接原路后退。如果后退比转弯更安全，就不必为了“向前开”而绕向警方。对方尚未被检测到时，不能保证所有交叉路口都不会发生意外交会。

### 5. 选定路线后连续执行，避免来回犹豫

每次选定一个明确的路口或藏点作为目标，按完整路线前进。不会在每个普通网格点仅因相对检测方向改变，就把整条路线推翻。

只有新的实际检测表明下一段存在紧迫交会危险时，才提前重新规划。当前紧急判断关注约 0.3 秒内的接触风险。到达目标后再进行后续选择，减少同一横线上反复折返。

### 6. 当前几种小偷模式的区别

| 模式 | 自然语言描述 |
| --- | --- |
| 藏身后智能逃跑 | 动态选择合适藏点及到达路线，停靠后检测到警方再撤离 |
| 藏身后预设路线 | 从预先生成的合法路线卡中选择路线，仍会结合当前检测筛选风险，不是无条件执行一条固定死路线 |
| 多路口连续逃跑 | 取宝后持续选择逃跑目标，不以长期停靠等待为主要行为 |
| 定点藏匿与下一藏点转移 | 更重视让警方搜索和转弯所需的时间，到藏点等待，暴露后转往下一藏点 |

“到藏点等待”是行为规则，不保证每次都有长时间停靠机会；警方持续接近时，小偷可能一直处于转移过程。没有可用藏点路线时，策略会退回普通逃跑选择。

## 三、警察策略

### 1. 开局走最快到达宝藏的路线

警方先按包含转弯耗时的最快路线前往宝藏区域，途中持续检测。实际检出小偷后，立即优先处理目标，不继续机械执行取宝路线。

警方不能远程读取“小偷已经拿到宝藏”这一仿真内部状态。是否检查过宝藏、当前看到了什么，才是它切换任务的依据。

### 2. 没有目标时，以有效探测覆盖为主

搜索时优先选择能够检查更多未覆盖位置的路线，尤其重视可能的藏点。比较路线时同时考虑新增探测范围、最近线索、行驶时间、转向时间和重复路段代价。

不要求每条黑线都必须开到，也不禁止必要的重复过路。若在一处就能探测到某条支路，可以利用检测范围减少绕行。完成一轮覆盖后，才开始新一轮搜索。

### 3. 长直道按完整巡查段扫描

中央长直道等连续通道可以作为整段扫描路线。选定后，即使暂时检测不到小偷，也继续扫描到该段末端，不因途经 T 型或十字路口而自动中断。

并非每次都必须走中央通道：如果该区域已经充分检查，其他路线能覆盖更多新位置，就选择其他路线。从长直道中部接入时，可以直接扫描前方剩余部分。

真正检测到小偷时可以中断巡查去追踪，未完成的巡查任务保留。覆盖记录只根据实际检测过程更新，不把计划经过的位置提前算成已检查。

### 4. 检出立即追踪，丢失后沿最后方向查找

有新检测时，向实际检出目标的位置追踪。短暂漏检不会立刻放弃，警方保留最后位置和运动方向作为线索。

如果还没到达最后检出位置，先去那里；如果已经沿目标方向越过旧位置，就不再回头追旧坐标。随后沿最后方向检查到直道末端，无新线索再恢复搜索；线索超过 12 秒也会失效。

恢复旧巡查时，从当前接入位置继续前方剩余路线，不为了补旧队列中的节点而无故倒回。跳过但没有实际检测到的区域仍保留为未覆盖，后续可以补查。新检出、线索到期或路段检查结束时，仍可能合理换向。

### 5. 小偷在单出口环路内时，优先判断能否堵口

当实际检测确认小偷位于上述单出口环路内部，而警方在圈外时，先找出它通向外部的唯一出口。

比较警方赶到出口的时间与小偷最快逃到出口的时间。如果警方能够抢先或同时到达，就直接前往出口堵截；赶不及则继续正常追踪。这个判断使用检测到的位置和地图，不能使用尚未检测到的小偷真实位置。

例如，小偷在右上角那一圈被检出时，警方可把 N027 作为堵截目标。到口后短时守候，满 2 秒后的决策释放堵口任务，随后 4 秒内不重复同一堵口。若新检测表明小偷已经离开、已来不及堵截，或旧线索超时，则取消堵口，避免长期守空口。

当前实现针对“只有一个外部入口、内部无分岔的环路”，没有声称能处理所有复杂封闭区域。堵口也不等于必然抓获。

### 6. 死路要有选择地检查

若完整死路支路及其中间位置都在检测范围内，连续三次未检出后可记为已查，不必再开进去。若覆盖不完整，就不能仅凭入口处没看见车，认定整条死路为空。

新的侧向检测指向死路时，应优先返回核查。普通没有线索的死路纳入整体覆盖搜索，避免不断插入临时绕行任务而破坏完整巡查。

### 7. 接触后立即结束比赛

仿真按双方连续运动中的二维距离判断抓捕，包括交叉路口交会、原地停靠和检测盲区。是否抓到由接触条件决定，不要求警方或小偷先识别到对方。

## 四、使用边界与后续落地

以上描述对应当前离线程序，不代表实车已经具备同等定位、测距和目标识别能力。当前尚未完整模拟制动与加速、车身旋转包络、循迹偏差、定位误差、掉宝及取宝机构。

路线和藏点采用启发式选择，单组回放不能证明胜率或全局最优。双方检测不到的信息不会因为地图已经烧入芯片而自动获得。

后续移植需要把策略输出的“下一节点、行进方向、停靠或追踪目标”交给实际循迹和底盘控制，并验证路口识别、位置更新、传感器覆盖和真实动作耗时。本次仅整理文档，没有修改策略代码、STM32 工程或执行固件编译。

验证状态应按实际工作区分：本策略目前完成的是离线仿真测试，尚未完成硬件验证；后续若固件仅完成编译，应记录为“仅编译通过，尚未完成硬件验证”，不能把该表述当作本次已编译的结论。
