# 16F 小车转向与车身碰撞仿真模型

更新日期：2026-10-12。独立回放目录：`Tools/TreasurePursuitSimulator/variants/16f`。

回放地址：[16F 车身转向回放](http://127.0.0.1:8765/variants/16f/replay.html)。旧的 16E 回放和 `Thief16E_VisibilityEscape_FourLaser_Test` 工程保留。368 个基线文件的 SHA256 核对一致。本次仅增加桌面仿真文件，没有改动 MCU 固件、引脚、PID 或电机控制。

## 一、画面和抓捕的变化

原来的车是圆点或菱形，90°转向开始时立即改变车头方向，然后等待转弯时间。抓捕使用两车中心距离不超过 0.18 米的判据。

16F 为两车绘制带四轮、车头箭头、车尾标记的二维车身。地图、道路连接、N001 等稳定编号以及蓝色警方实线、橙色小偷虚线保持原样。车身、车轮均画在碰撞外包络以内。

- 两车的矩形外包络均采用长 **190 mm**、宽 **198 mm**。用户同意采用 `Docs/04_硬件清单.md` 的名义尺寸；这不是含灰度板、轮胎、线束等突出部分的实测整车尺寸。
- 90°转向的角度连续变化，开始时保持原车头方向；制动等待之后角速度平滑增加、再降低。白箭头指出车头，红色短线指出车尾。
- 前进改为倒车时，车身不旋转 180°。车辆经过换向等待后沿相反方向移动。
- 裁判检查有朝向的两个矩形外包络。**轮廓首次接触立即判抓捕并冻结两车**，终局红点表示边界接触位置。
- 判定覆盖两个记录帧之间的运动和车角扫过，快速交会和原地旋转也参加检查。绘图线宽、文字和宝藏图标不参加碰撞计算。

可使用“显示车身碰撞轮廓”“跳到首次转向”“跳到车身接触”和 0.25 / 0.5 倍慢放。节点及路段开关、点击信息和 JSON 导出保留。编号布局使用旋转车身的包围框避让车身。

## 二、转向模型的准确性边界

当前采用**路口中心固定、车身连续旋转的运动学近似**。直行和倒车沿原地图中心线运动，速度、逻辑路线耗时和 C 规划器沿用 16E。

现有实车程序先约 100 RPM 前推 180 ms，再主动制动、四轮停稳确认、差速旋转；当前 YAW 阈值为 45°，之后前进并重新识线。16F 用 45°作为画面动作阶段标记，但没有把寻找新黑线时的前移路径伪造成已测出的圆弧，也没有改动实车的转角参数。

本版沿用 C 规划器的 **0.768 s 转弯额外时间预算**。其来源是 2026-10-06 全图日志的节点间时间减去名义直段时间，是规划代价，**不是实测的纯 90°原地旋转时间**。该趟旧控制参数与现在的 16E 也不同。制动占比 24% 和平滑角速度曲线是显示与碰撞所用的近似参数，不是新的实车测量结果。

角度曲线在制动区间保持不变，剩余时间使用 `3u²−2u³` 插值，不超出目标角度。碰撞计算与显示读取同一车身中心和同一角度。将前推、重新识线的整个流程时间再次叠加到按全长计算的直行时间，会重复计入位移，本版没有这样处理。

尚未模拟的部分包括：转向前推及找线的实际车身位移、车身惯性滑行、轮胎打滑、循迹摆动、车身与灰度板安装偏置、PWM 到角加速度的实际关系。检测仍沿用 16E 的理想地图轴向四方向光束；正在旋转时的真实光束方向与误差尚未标定。小偷移动期关闭检测、停稳后检测，仍由原 C 门控处理。

若下一步要贴近实车，优先补充侧上方定机位录像，画面有已知尺寸标尺，同时记录 STM32 的 `BRAKE / ROTATE / SPIN_END / REACQUIRED` 时间戳及 YAW。由录像测出转向时车身中心的位移、角度随时间变化；再替换这里的固定中心和角度曲线。只测一个“转弯总耗时”无法确定这些轨迹。

## 三、修改参数

参数在 [body_model.json](../Tools/TreasurePursuitSimulator/variants/16f/body_model.json)。警方、小偷可分别设置尺寸。

| 字段 | 当前值 | 单位与含义 |
| --- | --- | --- |
| `bodies.P.length_m / width_m` | 0.190 / 0.198 | 米，警方整车外包络长、宽 |
| `bodies.B.length_m / width_m` | 0.190 / 0.198 | 米，小偷整车外包络长、宽 |
| `turn.brake_fraction` | 0.24 | 转弯预算中保持原方向的占比，未实测 |
| `turn.pivot_angle_deg` | 45 | 度，显示旋转/航向收敛阶段的分界，不能用来修改真实固件角度 |
| `turn.center_path` | `fixed_at_track_node` | 目前仅支持路口原地转向；没有默默使用猜测的转弯半径 |
| `collision.contact_tolerance_m` | 0.0000001 | 米，数值接触容差，约 0.0001 mm；不代表实车测量精度 |
| `frame_period_s` | 0.02 | 秒，输出回放帧周期 |

例如实测整车长度 23 cm，应将相应车的 `length_m` 改为 `0.23`，随后重新生成。尺寸直接影响抓捕时刻，不能只在画面里缩放车辆而保留旧终局。

```powershell
& E:\Python\python.exe F:\Robot_Treasure\Tools\TreasurePursuitSimulator\variants\16f\simulate_16f.py
& E:\Python\python.exe F:\Robot_Treasure\Tools\TreasurePursuitSimulator\variants\16f\verify_replay.py
```

本机 C 回放仍使用 ARMCC 编译 16E 的实际规划器，在桌面 Cortex-M3 指令仿真器中调用；它不启动实车电机。构建产物位于本版的 `build/`，受 `.gitignore` 忽略。运行环境和原 16E 相同，不需要虚拟机或外部服务器。8765 本地服务仅用于在电脑中查看已生成回放。

旧配置里的 `capture_center_distance_m` 仍供原警方策略部分估算风险；16F 的终局裁判不读取该值，不据此判抓捕。未把车身模型或连续碰撞求解器移植进 STM32。

## 四、验证结果

- 18 项几何与运动测试通过，含迎面高速穿越、十字交会、边/角接触、近距离平行运动、包围圆重合但实际矩形未接触、转向起止连续、倒车车头不翻转、非有限坐标拒绝。另有 400 组对称性检查和 55 组密集采样/边界相交参照检查，包含仅旋转导致的中途接触。
- 五个回放均核对终局矩形接触、单次抓捕事件、终局立即结束、此前记录帧无重叠。原地转向专项在约 **0.408322 s** 接触，此时尚未转完；如果只看转向前后两个矩形会漏判。
- 同一地图 88 个标注节点、106 条标注路段，JSON 与 16E 完全一致。旧回放及 16E 工程 368 个基线文件 SHA256 不变。13 项 ARM 桥接/C 源码及头文件的报告哈希均核对通过。
- 离线执行页面实际脚本：不同颜色轨迹、车辆尺寸/角度、节点与路段点击、编号开关、碰撞轮廓开关、转向/藏点/决策/接触跳转、地图 JSON 导出通过。

| --- | ---: | --- |
| 完整开局，双方同速 | 37.784117 s | 取宝后车身接触，警方胜 |
| 完整开局，警方快20% | 25.426029 s | 取宝后车身接触，警方胜 |

这是每场单个种子的模型检查，不是胜率统计。新的碰撞判据与旧中心距离模型不同，不能直接把两版生存时长差异当作策略优劣。

验证文件见 `validation_result.json` 和 `ui_smoke_result.json`。`preview_map.png`、`preview_turn_contact.png` 由报告中的车身姿态用 Pillow 绘制，并已查看；它们是静态预览，**不是浏览器截图**。未执行实际浏览器布局/触控验证，也未做实车验证。本次仿真结论不能证明当前 STM32 实车能按相同轨迹转向。

沿用的 16E 实车工程验证状态仍为：`仅编译通过，尚未完成硬件验证`。

## 五、算法依据及文件清单

矩形使用分离轴检测；连续判定通过外包络分离量和最大角点速度约束安全步长，角点速度上界包含平移速度和 `|角速度|×包围半径`。包围圆只用于快速排除距离很远的车辆，不用来判抓捕。迭代无法收敛时抛出错误，不把它当作未相撞。

连续运动判定参考 [Erin Catto：Continuous Collision，GDC 2013](https://box2d.org/files/ErinCatto_ContinuousCollision_GDC2013.pdf) 关于时间内首次接触及包含旋转的保守推进方法。本项目自行实现小规模矩形求解，没有引入 Box2D、ROS 或服务器运行时依赖。

本次所有新增文件和变更范围见 [16F 文件清单](../Tools/TreasurePursuitSimulator/variants/16f/FILE_MANIFEST.md)。未执行 `git add`、提交或推送。
