# 多出口藏点与等待朝向：16G 独立实验

日期：2026-10-12。回放：[16G 多出口与朝向对照](http://127.0.0.1:8765/variants/16g/replay.html)。原 [16F](http://127.0.0.1:8765/variants/16f/replay.html) 保留。

用户提出等待方向不利、希望藏点有多条路脱身。该建议有道理，但道路条数、车头方向、警方可能的来向和抵达藏点的路线要一起比较。一个点有四条路，并不意味着它一定比三出口的点安全。

本版是独立实验，**未作为 16F 的默认替代策略**。11 个候选藏点全部是已有地图中的真实 T/十字路口，没有新增地图路口，也没有将路段中间的位置伪装成灰度定位点。

## 一、策略改动

1. **至少三条真正活路。** 离线从地图中剔除死支路和单入口口袋区域。沿每个出口跟踪至下一处至少有三条真实活路的分岔；只有通向不同下一分岔的出口才计数。道路最终仍可能汇合，这不是三条永不相交路径的证明。
2. **车头和车尾都有出口。** 停车轴必须前后均通向有效道路。排除整条停车轴超过 1.2 米的方向，避免在很长的直道上等待；这是一项启发式筛选，不能保证避碰。
3. **联合比较藏点、到达路线与停车朝向。** 候选状态包含节点、行进方向与前进/倒车模式。比较前后到下一处有效分岔的时间，惩罚较慢的一端，同时考虑前方的换线时间。最终方向由真正的到达路线实现，没有瞬间摆车头或新增尚未实现的停车转向动作。
4. **保留路线风险代价。** 原搜索用风险惩罚比较通向同一状态的路线，但选目标时只减去到达时间。16G 改为减去包含这些惩罚的搜索代价，减少“藏点分数高就压过抵达路线风险”的倾向。它仍是有限状态启发式，不是全局最优或获胜证明。
5. **先沿现有停车轴离开，再换线到下一藏点。** 检出警方后，禁止向已经检出的来车方向出发；先前进/倒车离开，再按道路连接转向。保留路线承诺、避免立即折返、冷却藏点与应急撤离逻辑。

前往宝藏的用户指定路线保持原样：N054 → N053 → N044 → N036 → N035 → N034 → N033 → N025 → N015 → N006 → N005 → N004，经过宝藏不停。首次藏点设为 **N038 四出口路口**，用于固定地图上的独立对照；后续藏点由 C 算法根据实际激光线索选择。首次固定 N038 不代表已经证明它是全图最佳藏点。

方向还需要考虑来车：如果停车轴与警方追来方向平行，往往容易沿同一条线被追；垂直方向可能让警方增加转弯。实验曾用“警方从宝藏到藏点的最快地图路线”作为来向先验，但两种速度场景没有同时改善，因此**该权重默认关闭**。猜测不会伪装成激光已检出的事实。物理试验需要覆盖不同来向，不能只依靠同一个地图先验。

小偷仍在移动时关闭激光、停稳后检测；范围仍为两格 0.6 米。道路投影、场界和质量/稳定帧筛选沿用 16E。C 规划器只接收自身地图位置及激光实际检出的距离/方向，未获得仿真中警方的隐藏全局坐标。

## 二、候选藏点和画面

候选节点：**N011、N012、N013、N021、N023、N038、N039、N056、N059、N062、N063**。N011、N038 为四出口，其余为三出口。N044 虽然图上有三条线，但其中一条是死支路，只有两条真实活路，本版不把它作为藏点。N008/N009/N018/N019/N026/N027/N028 的单入口区域及很长轴的 N076 也不作为藏点。

回放增加“显示可藏点与停车轴”开关。绿色圈是候选藏点，绿色双向箭头是计划停车轴；橙色点线仍是实际已选转移路线。点击候选节点可查看每个方向的下一分岔、路径和预计耗时。停车信息面板列出车头方向、前后分别能走到哪个分岔。

数据来自 `ThiefMapTopology.h` 与 `Tests/hide_catalog.json`。时间包括既有规划启动和沿途转弯成本，长度沿用名义地图，尚未实地标定。坐标、88 个节点编号、106 条路段及导出 JSON 与 16F 一致；19×19.8 厘米名义车身、连续转向和车身接触判据也一致。

## 三、实际仿真结果

所有下列结果都是当前模型下的桌面仿真，**不是实车成绩**。理想定位、固定转向中心、未实测惯性与找线位移的限制沿用 [16F 模型说明](14_小车转向与车身碰撞仿真模型.md)。

### 相同位置的朝向专项

N038 持宝等待，警方从 N040 向左接近，初始相距 0.6 米；只改变小偷初始车头方向。两车同速，使用同一传感器参数、种子和车身碰撞判据。

| N038 停车方向 | 运动效果 | 首次接触 |
| --- | --- | ---: |
| 横向朝西，前后沿东西轴 | 沿来车所在横线离开，在下一拐弯被追上 | 1.001963 s |
| 纵向朝北，前后沿南北轴 | 先离开该横线，再到下一藏点转移 | 12.896442 s |

两场最终都被抓。该结果支持“等待朝向会影响逃跑”的判断，不能外推为纵向停车在任何来向下都更好。

### 完整比赛复核

开发使用种子 7/8，复核使用未用于开发的 10/11/12。双方正常出生、同一警方策略、传感器、速度与 16F 车身碰撞判据；每个速度条件、每版各复核 3 次。

| 场景 | 16F 平均持续 | 16G 平均持续 | 小偷获胜 |
| --- | ---: | ---: | --- |
| 双方同速 | 37.784117 s | 28.532011 s | 两版均 0/3 |
| 警方快 20% | 25.426029 s | 25.761864 s | 两版均 0/3 |

16G 在同速场景下降约 9.25 秒；警方快 20% 时仅略有延长。**不能据此说新策略整体更好，也不能把专项方向优势当作比赛胜率提升。** 因此保留 16F 基线，将 16G 作为多出口/朝向对照实验。

当前不足包括：藏点的局部出口多，但到达路线可能先暴露；更有利的朝向也可能要求抵达时绕行；警方实际来向可能与地图先验不同。下一步应优先检查到达藏点前的首次曝光、已见警方的可能追击路线、出口是否很快汇合，再决定是否替换基线，不能只加大出口数量权重。

## 四、新工程与参数

新工程：[Thief16G_MultiExitHide_FourLaser_Test.uvprojx](../STM32/Keil_Project/Thief16G_MultiExitHide_FourLaser_Test/MDK-ARM/Thief16G_MultiExitHide_FourLaser_Test.uvprojx)。它是 16E 工程的独立复制，未覆盖旧工程。

主要参数在 `Algorithm/ThiefStrategy/ThiefStrategyConfig.h`：

| 宏 | 默认 | 作用 |
| --- | ---: | --- |
| `THIEF_INITIAL_HIDE_NODE` | 38 | 首次固定藏点，后续仍在线选择；0 为在全部合法点中评分 |
| `THIEF_HIDE_EXIT_WEIGHT` | 1800 | 第三/第四活路的评分权重，不是实测量 |
| `THIEF_HIDE_AXIS_WEIGHT` | 2 | 前后较慢出口时间的惩罚权重 |
| `THIEF_HIDE_FORWARD_WEIGHT` | 1 | 前方到下一分岔时间的惩罚权重 |
| `THIEF_HIDE_ALIGNED_PENALTY_MS` | 0 | 基于猜测来向的平行停车惩罚试验，默认禁用 |

本版没有调整巡航转速、转向 PWM、PID、YAW 阈值、CubeMX 引脚或外设初始化。117 个 Core/Control/Hardware/Drivers/System 源文件与原工程逐字节一致。新串口诊断行：

```text
HIDE_V4 NODE=N038 BODY=1 EXITS=4 AXIS_BRANCH_MS=526
```

`BODY=0/1/2/3` 分别为北/东/南/西。`EXITS` 为真实活路计数；`AXIS_BRANCH_MS` 是前后出口中较慢一端到下一分岔的规划时间，不是新实测数据。

算法仍为 704 个节点/方向/模式状态上限，工作区 **13,269 字节**；没有堆分配或递归，也没有运行时服务器依赖。Keil ARMCC5 全量编译：**0 Error(s), 0 Warning(s)**，Code 38,424 / RO 6,552 / RW 324 / ZI 34,044 字节，Flash 合计 44,976 字节、RAM 合计 34,368 字节，均在当前目标容量内。板上运行时间是否满足 100 ms 规划预算仍需实测。

**仅编译通过，尚未完成硬件验证**。本次没有自动烧录或运行实车电机。
