# 蓝牙记录路段与转弯实测数据

整理日期：2026-10-06。目标是小车预存地图与路线，自动采集前进路段和左右转数据，用于更新策略仿真。倒车暂不纳入。当前软件入口是独立工程 `Gray12_MapRoute_Calibration_Test`，详见第 10 节；前面保留测量边界及早期仅日志方案作为参考。尚未得到实车标定结果。

## 1. 能完成什么

可以让车载 STM32 在动作发生时记录时间、位置标记和运动数据，经已连接的蓝牙串口传到电脑，再按路段和转弯分类统计。蓝牙提供传输通道，不负责测量。

目前不能承诺一个未经验证的误差百分比。距离基准、路口识别时刻、传感器安装偏移、控制周期、陀螺仪更新和车轮打滑都会影响准确度。应先通过一条已知直道和一个转弯验证测量方法，再扩大到全图。

## 3. 时间在车上记录，电脑保留原始记录

事件发生时，先在车上保存源时间戳，再把完整记录送入发送队列。电脑收到消息时也可以记接收时间，但接收时间仅用于检查传输，不用于计算小车动作耗时。

蓝牙缓存、串口排队和电脑调度会改变消息到达时间。即使消息晚到，只要车上原始时间戳及记录完整，仍可用源时间差计算动作耗时。

记录至少带有测试批次、启动标识、连续序号和校验。出现丢包、源时间重置、计量缓冲区溢出、路口顺序不符或转向故障时，将相关样本标为无效。尽量先缓存短小事件记录，在不阻塞控制的情况下发送；必要时由用户停车后导出。

不同电压、载荷、目标轮速、控制参数和测试批次分开保存。软件时间计数的回绕应通过无符号差值处理，重启不能当作同一连续测试。

## 4. 直道路段怎么测

### 测量基准

每个速度结果必须同时给出实际测量距离、两个参考事件和耗时：

`平均速度（米/秒） = 实际测量距离（米） / 源时间差（秒）`

先定义车体的参考点和路段边界，再用尺子核对距离。灰度板首次看到岔路并不等于车体参考点已到路口中心。相同安装偏移在相同方向、相同边界条件下可能相互抵消，但遇到不同路口形状或转弯就不能默认抵消。

若从“转弯完成后的出弯位置”计时到“下一个路口首次检测”，这只是道路的一部分，不能直接拿整条 Sxxx 的中心间长度除以这段时间。需要测量对应区间的距离，或校正两端偏移。

### 建议同时保留两种数据

| 数据 | 含义 | 用途 |
| --- | --- | --- |
| 路段通行耗时 | 统一边界之间的实际耗时，注明是否包含加速、减速、找线或转弯 | 估计实际路线到达时间 |
| 稳定直行平均速度 | 转弯、起步、找线以外的已标定直线区间距离除以耗时 | 检查真正的直行速度 |

编码器轮速用于辅助记录加速和波动。轮速 RPM 不是车体对地速度，换算需要核实有效轮周长及编码计数，并检查打滑；不能只用目标 RPM 作为实测速度。

同一路段按 N001→N002 和 N002→N001 分开统计。启动进入、转弯后进入、连续直行通过也分开记录，避免把不同进入状态平均成一个“准确速度”。

## 5. 转弯怎么测

优先测两个耗时：

1. **旋转阶段耗时**：开始施加转向动作，到结束该旋转阶段。配合实际航向角变化，可计算平均角速度。
2. **整个转弯流程耗时**：识别并进入转弯流程，到重新稳定沿目标线路循迹。包含受控接近、制动、旋转和出弯找线，通常更适合估计比赛到达时间。

建议分别记录：路口检出、制动开始、旋转开始、旋转结束、恢复循迹、稳定确认。稳定判据需要在新标定工程中明确，例如有效灰度持续满足条件并恢复合适航向；单次检出黑线不等于已稳定。

左右转分开，同一方向在不同进入速度、路口类型及出弯条件下也分别统计。

重要的现有代码边界：参考工程旋转阶段的航向目标当前是 **50°**，随后进入向前找线。其 `TURN_DONE` 不能直接当成“完整 90°转弯结束”，也不能用 `90° / 该阶段耗时` 冒充实际角速度。要记录实际航向变化、数据新鲜度及后续找线完成事件。

实际角速度可以使用 `实际角度变化 / 对应旋转阶段时间`。角度跨越 ±180°时需要处理回绕；有传感器等待、灰度备用结束或转弯超时的样本应单独标记。

回填仿真参数时要避免把接近/出弯的平移时间，同时计入路段时间和额外转弯时间。先固定统一的时间分配口径，再计算或拟合转弯附加代价，不能把整个流程耗时无条件叠加到整段距离/直行速度上。

## 6. 怎样对应全图

按已知起点、已确认朝向及预定路线记录经过的节点和路段。结合路口形状、航向和编码器辅助检查步骤是否匹配。相同形状的 T 型路口不能仅凭一次灰度识别确定全局编号；路线步骤错位后，后续样本不能继续当作正确标定。

宝藏点 N005 是任务位置，普通原图细分点也不是新增灰度路口。没有对应物理检测事件的边界，需另设已知标定标记或使用经校正的里程判断，并注明定位误差。

全图可以分成多条短测试路线，不要求一次自主跑完整张图。倒车未完成时，死路可由用户停车并手动重新放置，作为新的测试批次；不能声称一条没有倒车或掉头能力的路线能够覆盖所有死路并自动返回。

推荐顺序：通信和记录完整性 → 一条已标定直道 → 左右转各一个 → 多路口短路线 → 分批覆盖其余路段。每种条件重复若干次，建议初始收集 5～10 次，再根据实际波动决定是否加测。

## 7. 最终输出

- 按 Sxxx、起止 Nxxx、方向和进入状态列出距离来源、通行时间、平均速度及样本数。
- 按转弯位置、左右方向和进入状态列出旋转耗时、总流程耗时、实际角度及结束条件。
- 报告中位数、范围和波动，并保留全部原始有效/无效样本及原因，不只给一个平均值。
- 列出未测路段、未标定距离、异常记录和覆盖缺口；不给没有测到的道路编造结果。

可达到的误差应通过长度复测、已知事件的同步视频等独立检查及重复运行来评估。微秒时间字段不会消除路口检测、陀螺仪采样和安装偏移造成的误差。

## 10. 当前方案：地图路线执行与仿真参数采集

用户明确需要小车知道地图和测试路线，再用它跑出的数据更新策略模拟；人工给普通转弯日志配编号不满足当前目标。因此新建 `STM32/Keil_Project/Gray12_MapRoute_Calibration_Test`，从仅日志工程复制，不覆盖原工程。

- ROM 表预存 88 个节点、106 条路段及 21 条前进路线，规划覆盖 212 个有向路段条目。路线、节点、长度及朝向在开始前进行表内连接核对。
- 路口动作由表中决定，支持直行穿过岔路、左转、右转及终点停车；前灰度用于观察路口，编码器名义里程用于检查位置推进是否明显异常。方向不再由“优先右转”替代地图路线。
- 知道地图不等于任意位置自动定位：用户按 R 路线的已知起点和朝向摆车，之后用路口序列推进位置估计。相同路口、漏检、轮径误差和打滑仍需短路线实测核对。异常时制动停车，不盲目累计节点。
- 倒车暂不做，原地 180°能力尚未确认。13 个死路端点使一趟连续覆盖需要额外换向能力；当前采用分批自动路线，路线末端停车后用户重新摆到下一起点。没有把这称作连续全图自主覆盖。
- N005 位于直道内部，两侧 S 路段保留编号但合成一个计时区间，报告明确哪些数据共用区间，不能冒充分别识别到 N005 的独立测量。
- MT2 行记录 STM32 源时间、R 编号、步骤、两端 N 编号、地图/路线签名和运动传感器数据。`analyze_routes.py` 自动对应 S 编号，不再需要填写旧 MT1 的路段分配表。
- 输出保留真实源时间差、整个转弯流程、各方向样本及缺口。未测路段不补造。当前速度换算使用规则地图距离或硬件清单名义轮周，转弯额外代价由整个相邻节点通行时间扣除基础直行时间估计，不把完整转弯流程重复追加到路段平移耗时。
- 明确选择测得的车辆角色，并确认起始摆放及实际路线后，可以生成独立仿真配置。新增 `motion_profiles` 让有向路段速度和该车转弯代价用于寻路及实际运动；另一辆车、未测方向和倒车仍沿用原参数。没有把合成测试数据写入默认策略配置或回放。

操作入口、生成命令、按键说明及接线表见 `Tools/MapTimingLogger/README.md`；各条起点及路线见 `map_routes.md`。首次应只验证 R001 的首个路口及右转，确认实际路口、90°对线和日志后由用户按停止键结束，再逐步延长路线。最终编译、离线测试及完整差异清单在新工程 `delivery_manifest.json` 中记录。**仅编译通过，尚未完成硬件验证**。
