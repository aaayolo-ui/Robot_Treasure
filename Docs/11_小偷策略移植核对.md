# Thief16A 小偷策略移植核对

日期：2026-10-11。用户反馈：实车在改接四激光之前，运行 Thief16A_FrontLaser_MapStrategy_Test 时，路线与策略不一致。当前实体接线已经更改。因此，新接线不解释之前的偏离，但旧固件不适合直接用于现在的接线。

本记录核对当前工作区源码和现有离线检查，不代表读取了车内固件，也没有获得第一次偏离节点的实车日志。未修改控制代码、编译、烧录或驱动电机。

## 核对结论

完整仿真小偷策略尚未移植到 Thief16A。当前 STM32 工程是单前激光条件下的简化实现，不能视为仿真策略的等价版本。

用户指定取宝路线已写入当前规划器，且规划结果确实传给执行层。未发现执行器仍使用原全图标定路线的调用。因此，“拿宝之后藏匿和逃跑不符合策略”有直接的移植缺失证据；“拿宝之前走错路”的实车原因仍未确定，不能用移植不完整直接解释。

## 指定取宝路线的连接链

1. `ThiefMapPlanner.c` 的 `initial_treasure_path` 保存：54、53、44、36、35、34、33、25、15、6、5、4。
2. `App_ThiefStrategy_Init` 调用 `ThiefMapPlanner_PlanInitial(&thief_plan)`，固定取宝前缀后拼接去 N059 的最短路。
3. `Route_Start` 调用 `MapRouteNavigator_StartRuntime`，传入 `thief_plan.route` 和 `thief_plan.steps`。
4. `Route_HandleJunction` 获取当前步骤的 action，进入直行、左右转、换向或停车状态。
5. Keil 工程包含该规划器、运行时导航器及应用源文件。

取宝前需要的动作：N053 右转、N044 直行、N036 左转、N035/N034 直行、N033 右转、N025/N015 直行、N006 左转。宝藏 N005 是路段内部点，被合并为 N006→N004 的直穿步骤，不等待灰度路口事件。

现有 Python 离线检查结果：初始路线共 6600mm，节点序列为：

```text
N054 N053 N044 N036 N035 N034 N033 N025 N015 N006 N005 N004
N014 N015 N025 N033 N049 N061 N070 N069 N060 N059
```

此检查验证地图连接、固定前缀和算法约束；它是 Python 对规则的镜像，不是 STM32 二进制运行或实车路径证据。

## 仿真策略与当前 STM32 实现差异

| 规则 | 电脑仿真 | 当前 Thief16A |
|---|---|---|
| 初始取宝 | 仿真按预计耗时规划；实车用户另指定固定路线 | 指定固定路线已经接入 |
| 首藏点 | 根据路线风险、警方先验和藏点质量评分 | 固定 N059 |
| 藏点安全 | 检查环路核心、单出口口袋、长直道和可靠退路 | 静态候选节点表，没有同等拓扑筛选过程 |
| 远离警方来路 | 比较近期线索或警方预计来路 | 逃跑第一段强制沿车头反方向倒车，后续没有警方来路模型 |
| 路线代价 | 前进、倒车、转弯、换向耗时 | Dijkstra 只累计路段长度 |
| 相遇风险 | 评估警方到达时间及沿途接触风险 | 未实现 |
| 下一个藏点 | 综合搜索难度、检测暴露、出口、路程与风险 | 主要最小化距目标逃跑长度1500mm的差值 |
| 已暴露藏点 | 30秒冷却并降低重复路线倾向 | 只排除当前及上一个藏点；没有同等冷却和路线历史评分 |
| 行驶途中检测 | 新检测可触发紧迫避险 | USART2 在移动期间关闭；只在藏点停稳后启用前激光 |
| 四方向信息 | 仿真提供四方向有限检测 | 当前仍只有前激光接收和门控；四路接线文档不等于驱动已实现 |

尤其是逃跑规划函数没有接收测距命中坐标、警方速度、最近线索时间或警方可能路径作为参数。前激光距离用于决定是否触发逃跑，但没有用于计算下一条路线与警方的交会风险。这是策略融合的实际缺口，不是调 PID 可以补齐的问题。

## 取宝过程中可能错位的执行缺口

`MapRouteNavigator_Arrive` 不核对实际路口完整类型，只检查里程大致范围，然后认定到达当前步骤的目标节点。虽然步骤存有 `expected_ports` 和 `target_kind`，前者没有用于实际到达判断，后者只在路线静态校验中与地图节点核对。

300mm 路段允许到达范围约70～580mm。处于此范围的错误灰度支路事件有可能推进路线；低于下限的事件会进入故障，而不是被当成无关图案忽略。左右转前还会检查所需侧支路，但这不能证明它就是正确节点；直行通过也不等于识别了节点编号。

如果一个路口被提前误认或遗漏，后面的动作表即使正确，也可能在错误位置执行。当前没有完整的定位可信度、拓扑不一致拒绝和重定位流程。

当前控制参数核对：巡航260RPM，起步/转后200RPM，转向PWM550，转前100RPM行进180ms，陀螺仪角度阈值4500即45°（注释仍写50°）。这些是源码现值，不能据此推断此前实际烧录版本或认定实车原因。角度阈值之后还有前进找线阶段，不应直接等同于最终车身转角。

## 后续修复的顺序

1. 在独立复制工程适配目前接线：取消 TFT、左前编码器B相迁移到PB14并跨GPIO读取、四路激光独立解析、PB10单向日志。
2. 先验证固定取宝路线执行：日志输出完整计划，以及每次实际灰度事件、预期节点、里程、接受/拒绝原因和转向完成角度。
3. 让真实路口特征、里程窗口和朝向共同确认节点，避免只靠事件计数假定坐标；窗口与传感器相对车中心偏移需实测。
4. 将仿真中的藏点拓扑筛选、警方先验/检测记忆、转向与换向代价、交会风险、藏点冷却和完整路线承诺逐项移植。
5. 单独验证固定取宝、定点等待、检测后转移到下一个安全藏点，最后再做对抗验证。代码/离线检查与硬件结果分别记录。
