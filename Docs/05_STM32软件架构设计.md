# 05 STM32 软件架构设计

本文描述与当前硬件基线对应的软件边界和接口规划，不在本次文档中虚构 STM32F103RCT6 的具体引脚分配。

## 1. 分层结构

```text
main.c
  └─ Control：RobotState / Strategy / FaultManagement
       └─ Algorithm：GrayPosition / SpeedPID / TrackPID / IntersectionDetection / Navigation
            └─ Hardware：Motor / Encoder / MD240A / NCHD12 / ToF / Infrared（备用/对比） / Power / Buzzer_LED
                 └─ STM32 HAL、定时器、I²C、GPIO、UART
```

| 层 | 模块 | 职责 |
|---|---|---|
| Hardware | `Motor`、`MD240A` | 四个独立 PWM、方向与使能输出；执行斜坡、反转保护和停机 |
| Hardware | `Encoder` | 四组 AB 相计数、速度计算、零速/堵转观察 |
| Hardware | `NCHD12` | PCA9555 配置、双模块读取、位序归一化、超时与错误状态 |
| Hardware | `ToF` | 候选 ToF 模块的 UART 接收、数据帧解析、距离有效性、超时和方向距离接口 |
| Hardware | `Infrared`、`Power`、`Buzzer_LED` | 普通红外备用/对比采集、可选电池 ADC、声光输出 |
| Algorithm | `GrayPosition`、`TrackPID` | 根据当前主灰度模块计算横向误差、线宽和路口特征 |
| Algorithm | `SpeedPID`、`IntersectionDetection`、`Navigation` | 四轮闭环、路口识别与路径动作 |
| Control | `RobotState`、`Strategy`、`FaultManagement` | 模式选择、比赛策略、故障降速/恢复/停车 |

## 2. 控制链路与周期

```text
前部或后部灰度模块
  ↓ 横向误差、线宽、路口特征
循迹外环
  ↓ 左右侧目标速度
四轮目标速度分配
  ↓ 四轮编码器速度 PID
MD240A 四路 PWM、方向、使能
```

基础阶段可让同侧前后轮使用相同目标速度，但四个独立反馈和独立输出能力必须保留。前进时以前 NCHD12 为主，后退时以后 NCHD12 为主；可用另一模块作为状态判断辅助，但绝不同时运行两个互相冲突的循迹 PID。

推荐基础控制周期为 10 ms（100 Hz）：

1. 读取前 NCHD12；
2. 读取后 NCHD12；
3. 检查有效性和时间戳；
4. 计算灰度位置误差；
5. 读取编码器速度；
6. 执行状态机和 PID；
7. 更新四轮目标速度；
8. 更新 MD240A 输出。

单块 I²C 读取约 0.2～0.5 ms，两块顺序读取约 0.4～1 ms，I²C 带宽不是瓶颈。初期通信测试用 50 Hz，基础循迹 100 Hz，高速和路口测试可提高到 100～200 Hz。

## 3. NCHD12 / PCA9555 驱动规范

两块 NCHD12 共用一条 I²C 总线，驱动层仅保存 7 位地址：

```c
#define NCHD12_FRONT_ADDR  0x20U
#define NCHD12_REAR_ADDR   0x21U
```

HAL 的 `DevAddress` 使用 `addr7 << 1`。`0x20` 是 7 位地址；`0x40` 和 `0x41` 分别是默认 8 位写/读地址表示，绝不能混用。

初始化显式写入 PCA9555：Configuration Port 0（`0x06`）=`0xFF`、Configuration Port 1（`0x07`）=`0xFF`、Polarity Port 0（`0x04`）=`0x00`、Polarity Port 1（`0x05`）=`0x00`。读取从 Input Port 0（`0x00`）连续取两字节：

```c
uint16_t raw = ((uint16_t)high_byte << 8) | low_byte;
uint16_t sensor_bits = raw & 0x0FFF;
```

bit0～bit11 对应 12 路灰度；低字节是前 8 路，高字节低 4 位为余下 4 路，高字节高 4 位未用。该接口没有 CRC、长度字段或私有数据帧。

```c
typedef struct
{
    uint16_t front_bits;
    uint16_t rear_bits;
    uint32_t front_timestamp_ms;
    uint32_t rear_timestamp_ms;
    uint8_t front_valid;
    uint8_t rear_valid;
} GraySensorData;
```

上层物理方向统一为 bit0=车辆左侧最外探头、bit11=右侧最外探头。前后安装方向可能不同，须由 `NCHD12_NormalizeFront()` 和 `NCHD12_NormalizeRear()` 分别处理；实际反转规则等待逐路遮挡实测后确定，不能预先写死。

建议接口为：`NCHD12_Init()`、`NCHD12_Read(addr7, bits)`、`NCHD12_ReadFront()`、`NCHD12_ReadRear()`、`NCHD12_NormalizeFront()`、`NCHD12_NormalizeRear()`、`GraySensor_Update()`、`GraySensor_CheckTimeout()`。

读取失败不得伪装成合法全 0。除结构体状态外应保存 `front_error_count`、`rear_error_count`、`front_last_update`、`rear_last_update`，并处理 I²C NACK、总线卡死、数据不更新、长期全 0/全 1、脱线及主循迹模块失效。前进时前模块、后退时后模块连续失效，必须降速或停车，不得沿用旧数据高速行驶。

## 4. ToF 传感器驱动规划

在 `Hardware/` 层增加候选模块驱动文件：

```text
Hardware/
├── tof_sensor.c
└── tof_sensor.h
```

当前仅规划架构和接口，不创建未经验证的完整驱动代码。AI-1811 当前购买 1 个用于电脑串口测试，USB 转 TTL 不作为最终装车接口；最终装车时由 ToF 模块直接连接 STM32。AI-1811 的工作参数按当前购买款式记录为主动上报、UART、9600 波特率（不可调）、30 Hz 刷新频率（不可调）、50～4000 mm 测量距离、50 mm 盲区、约 25° 视场角、优先 3.3 V 供电和 3.3 V UART 信号电平。

单模块连接约定为：`V → STM32 3.3V`、`G → STM32 GND`、`T → STM32 UART_RX`、`R → STM32 UART_TX`。TX/RX 必须交叉连接，接线依据模块 `V/G/R/T` 标识，不依据线色。主动上报模式会连续发送数据；多个模块的发送端不能直接并联到同一个 STM32 UART_RX。

建议先规划以下接口：

```c
ToF_Init()
ToF_Update()
ToF_ParseFrame()
ToF_GetDistance()
ToF_IsValid()
ToF_IsEnemyDetected()
```

驱动应覆盖：

- UART 数据接收及接收时间戳；
- 数据帧边界、长度/校验等格式解析（具体帧格式须以实物资料和串口测试确认，不能预先臆造）；
- 距离有效性检查、50 mm 盲区处理、0 值/最大值/无效帧处理；
- 接收超时和连续无效数据处理；
- 距离滤波、连续多帧确认、进入/退出阈值迟滞，避免临界值附近反复跳变；
- 前、后、左、右方向距离的统一获取接口。

敌方检测不应只依据单次距离。候选四方向方案的最终数量、UART 数量和通信拓扑仍需在 CubeMX 中验证可用硬件串口、UART 引脚复用、调试串口占用、DMA/中断资源，并评估串口切换、外部多路复用或其他方案；不能提前声称四个模块已能直接接入四个独立 UART。后续多个 ToF 同时工作时的互相干扰也必须通过实测确认。

## 5. 电机、编码器与故障管理

11C 当前物理轮位基线为 MD240A A→`Motor_FR`、B→`Motor_FL`、C→`Motor_RR`、D→`Motor_RL`。这不是新车头下的方向控制结论：各通道前进电气方向、编码器逻辑符号、左右速度分组和底盘动作映射仍待重新验证。推荐 PWM 为 10 kHz。初期目标车速约 0.3～0.5 m/s，使用最大 PWM、加减速斜坡和速度 PID 避免 290 RPM 配 65 mm 轮胎带来的过快响应。

单电机堵转电流 3 A 接近驱动板 3.2 A 峰值，故障层必须在 PWM 超阈值且编码器速度连续 100～300 ms 接近零时停止相应电机、记录故障、延时恢复；连续故障转入停车状态。禁止高速直接反转。

## 6. CubeMX 资源需求

| 功能 | 资源要求 |
|---|---|
| 四个电机 | 4 路 PWM；方向、使能等 GPIO；MD240A 实际接口数量核对 |
| 四个编码器 | 4 组 AB 相，共 8 路输入；验证 TIM1～TIM4 编码器模式 |
| 双 NCHD12 | 一组 I²C（SCL/SDA） |
| 候选 ToF | 至少验证 1 路 UART 接收；四模块最终通信路径未定，需检查可用硬件串口、UART 引脚复用、DMA/中断资源 |
| 备用红外 | 是否保留为混合方案的一部分及其 GPIO 资源占用仍待决定 |
| 外围 | LED 输出、蜂鸣器输出、UART 调试、可选电池 ADC、备用扩展 |
| 调试 | SWDIO、SWCLK，且核对开发板实际引出脚 |

必须在 CubeMX 中完成 PWM 定时器、TIM1～TIM4 编码器模式、引脚复用冲突、I²C、UART、SWD、开发板实际引脚和 MD240A 实际接口数量的联合验证。具体引脚分配等待该验证完成后确定。
