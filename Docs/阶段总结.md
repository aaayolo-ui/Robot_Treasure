## 09｜Four_Motor_GroundStraight_Test（10F）

### 对应工程

`STM32/Keil_Project/Four_Motor_GroundStraight_Test`

### 阶段目标

在底盘落地条件下观察四轮独立闭环前进、后退、起停安全性和左右速度差异。

### 关键配置

- 前进四轮目标：+80.0 RPM；后退四轮目标：-80.0 RPM。
- 软启动：4.0 RPM / 100 ms，0 到 80 RPM 约需 2.0 秒。
- PWM 测试上限：300；最大运行时间：3 秒，到时自动停止。
- Kp=0.80，Ki=0.25，控制周期=100 ms，堵转持续时间=1500 ms。
- 停止或禁用时 PI 清零但编码器反馈继续更新；不使用 B 轮或左右固定补偿。

### 实际测试结果

- 前进方向正确，后退方向正确。
- 前进约 50 cm 时向右偏约 2～3 cm。
- 后退向左后方返回，轨迹大致回到原来的位置。
- 未出现原地旋转、单轮反转或明显失控。

### 已知问题

存在稳定轻微右偏，当前可接受，见 P005。

## 10｜11A｜12路灰度传感器 I2C 基础读取与通道映射

### 对应工程

`STM32/Keil_Project/Gray12_I2C_BasicRead_Test`

### 阶段目标

验证 12 路灰度模块的 I2C 基础通信、物理通道顺序、黑白极性和黑色通道数量统计，并保持电机处于安全禁用状态。

### 关键配置

- I2C1 使用 PB8/PB9 重映射，频率为 100 kHz；模块 7 位地址为 `0x20`，HAL 调用使用 `addr7 << 1`。
- 使用 PCA9555-compatible 访问方式：输入配置寄存器为 `0x06`、`0x07`，输入数据寄存器为 `0x00`、`0x01`。
- `RAW16` 为完整 16 位原始数据，`GRAY12 = RAW16 & 0x0FFFU`；B12～B15 不属于灰度通道。
- 通道映射为 P1=B0、P2=B1，依次至 P12=B11；黑色=1，白色=0。
- 结构分层：Core 仅保留 CubeMX 外设初始化和 App 调用；Hardware 包含 MotorDriver、Encoder、Key、NCHD12、UartDebug；User 为 `App_Gray12BasicRead`。
- 电机安全状态：Driver 禁用、STY 低电平、四路 PWM 为 0，未启动速度 PI。

### 实际测试结果

- 全白：`RAW16=0xF000`、`GRAY12=0x000`、`BLACK_COUNT=0`，P1～P12 均为 0。
- 全黑：`RAW16=0xFFFF`、`GRAY12=0xFFF`、`BLACK_COUNT=12`，P1～P12 均为 1。
- 仅 P1 为黑：`GRAY12=0x001`、`BLACK_COUNT=1`。
- 仅 P6 为黑：`GRAY12=0x020`、`BLACK_COUNT=1`。
- 仅 P12 为黑：`GRAY12=0x800`、`BLACK_COUNT=1`。
- 串口输出正常，P1～P12 通道顺序和 `BLACK_COUNT` 统计正确，灰度数据变化与模块指示灯一致。
- 测试全过程电机未运动；Keil 编译结果为 0 Error(s)、0 Warning(s)。

### 已知问题

曾发生设备地址可应答但 PCA9555-compatible 寄存器读写失败的情况；最终复测未持续出现，唯一根本原因尚未确认，详见 P007。

### 最终结论

通过：已完成硬件验证，可以进入后续灰度位置计算阶段。

### 下一阶段

灰度位置计算基础验证（加权位置算法）。

## 11｜11B｜12路灰度位置与横向误差计算

### 对应工程

`STM32/Keil_Project/Gray12_Position_Test`

### 阶段目标

基于 11A 已验证的单块 NCHD12 读取结果，验证 12 路二值灰度的加权位置、相对传感器中心的横向误差、无黑线和全黑状态判断；本阶段不执行巡线 PID、车轮差速修正、丢线搜索或路口识别。

### 软件结构与关键配置

- 工程以已验证可下载的 `Gray12_I2C_BasicRead_Test` 为完整模板复制，保留 `.uvprojx`、`.uvoptx`、ST-Link、SWD、Flash Algorithm 与下载配置；未修改引脚、时钟、I2C、USART、电机或编码器硬件配置，`.ioc` 仅改项目名称和文件名。
- `Core` 保留 CubeMX 初始化和 App 调用；`Hardware` 保留 MotorDriver、Encoder、Key、NCHD12、UartDebug；新增 `System/SystemTime`、纯算法 `Algorithm/GrayPosition` 和 `User/App_Gray12Position`。
- `GrayPosition` 不包含 HAL，不访问 I2C、GPIO、UART、定时器或电机，不使用 `float` 或 `double`；输入仅使用 `gray12` 低 12 位。
- 一个探头间距定义为 `100`，权重依次为：P1=-550、P2=-450、P3=-350、P4=-250、P5=-150、P6=-50、P7=+50、P8=+150、P9=+250、P10=+350、P11=+450、P12=+550。
- 坐标为传感器标签坐标：P1 一侧为负、P12 一侧为正，P6/P7 之间为 0；尚未绑定到车辆左/右方向。
- 黑色通道权重求和后除以黑色通道数量得到 `POSITION_X100`；中心目标为 0，因此 `ERROR_X100 = POSITION_X100`。
- `GRAY12=0x000` 为 `NO_LINE`、`VALID=0`；黑色通道数量 1～11 为 `VALID`、`VALID=1`；`GRAY12=0xFFF` 为 `ALL_BLACK`、`VALID=0`。无黑线和全黑均不伪装为有效中心位置。

### 软件自检与编译结果

- 9 组软件向量全部通过：`0x000`、`0x001`、`0x020`、`0x040`、`0x060`、`0x030`、`0x0C0`、`0x800`、`0xFFF`。
- Keil 使用 ARM Compiler 5.06 编译，结果为 0 Error(s)、0 Warning(s)，已生成 AXF 和 HEX。

### 实际测试结果

- 全白时输出 `STATUS=NO_LINE`、`VALID=0`；全黑时输出 `STATUS=ALL_BLACK`、`VALID=0`。
- 仅 P1 黑时 `POSITION_X100/ERROR_X100=-550`；仅 P6 黑时为 `-50`；P6/P7 同时黑时为 `0`；仅 P7 黑时为 `+50`；仅 P12 黑时为 `+550`，状态均符合预期。
- 黑线从 P1 一侧缓慢移动至 P12 一侧时，位置由负值经 0 向正值连续变化，整体方向正确，未发现突然反向跳变。
- 测试过程中电机未运动，STY/STBY 保持低电平、四路 PWM 保持 0；未运行速度 PI、巡线 PID，也未根据灰度误差控制车轮。

### 最终结论

通过：已完成单块12路灰度模块的位置与横向误差基础计算验证，可以进入车辆安装方向确认及灰度误差与车体方向关系验证阶段。

## 12｜11C｜灰度传感器安装方向与车辆横向误差符号确认

### 对应工程

`STM32/Keil_Project/Gray12_VehicleDirection_Test`

### 阶段目标

在 11B 已验证的灰度标签坐标基础上，锁定新车头下的灰度安装方向，并确认标签坐标转换为车辆横向误差后的符号正确；本阶段不实现新车头下的底盘映射或循迹控制。

### 软件结构与关键配置

- 工程结构为 `Core`（CubeMX 初始化与 App 调用）、`Hardware`（MotorDriver、Encoder、Key、NCHD12、UartDebug）、`Algorithm`（GrayPosition、GrayCoordinate）、`System`（SystemTime）和 `User`（App_Gray12VehicleDirection）。
- GrayPosition 保持标签坐标：P1=-550、P2=-450、P3=-350、P4=-250、P5=-150、P6=-50、P7=+50、P8=+150、P9=+250、P10=+350、P11=+450、P12=+550；P6/P7 之间为 0。
- 唯一安装方向配置为 `GRAY_MOUNT_P12_LEFT_P1_RIGHT`：P12 侧为车辆左侧，P1 侧为车辆右侧。
- 车辆坐标定义为左负、中心零、右正，转换规则为 `vehicle_error_x100 = -label_position_x100`。
- `NO_LINE` 与 `ALL_BLACK` 均保持 `LABEL_POSITION=INVALID`、`VEHICLE_ERROR=INVALID`，不伪造有效的零误差。

### 软件自检、编译与实机结果

- GrayPosition 自检为 `9/9 PASS`；GrayCoordinate 自检为 `PASS`，覆盖 UNKNOWN、两种安装方向以及 P12_LEFT_P1_RIGHT 下的 +550、0、-550 转换。
- ARM Compiler 5.06 编译结果为 0 Error(s)、0 Warning(s)，已生成 AXF 和 HEX；程序已下载并完成实机运行确认。
- P12 侧黑线时，`LABEL_POS_X100` 为正、`VEHICLE_ERROR_X100` 为负、`VEHICLE_SIDE=VEHICLE_LEFT`；中心时二者均为 0、`VEHICLE_SIDE=CENTER`；P1 侧时标签位置为负、车辆误差为正、`VEHICLE_SIDE=VEHICLE_RIGHT`。
- 运行期间电机未运动，STY/STBY 保持低、四路 PWM 为 0；未运行速度 PI、巡线 PID，也未根据车辆误差控制车轮。

### 新车头与物理轮位

从 11C 开始，原车尾重新定义为当前车头。已确认的物理轮位为 FL=B、FR=A、RL=D、RR=C；对应地，驱动通道 A=新右前 FR、B=新左前 FL、C=新右后 RR、D=新左后 RL，编码器 A/B/C/D 分别随对应电机处于相同物理轮位。

以下结论仍待独立验证，不能从旧车头下的结果推导：各通道“前进”的电气方向、编码器逻辑符号、前进/后退/左转/右转动作、左右轮速度分组、速度 PI 映射以及灰度误差到左右轮修正的控制方向。

### 最终结论

通过：已确认新车头下 P12 侧对应车辆左侧、P1 侧对应车辆右侧，车辆横向误差满足左负、中心零、右正。当前物理轮位已更新为 FL=B、FR=A、RL=D、RR=C；进入电机循迹前，必须重新验证新车头下的电机方向、编码器符号和底盘动作映射。

## 13｜11D-1｜新车头下单轮电气方向与编码器原始符号验证

### 对应工程

`STM32/Keil_Project/NewFront_MotorEncoder_Direction_Test`

### 阶段目标

逐通道验证新车头下 A/B/C/D 的物理轮位、电气方向与未经逻辑修正的编码器原始增量，为后续底盘映射提供已测数据；本阶段不运行速度 PI、整车自动运动或循迹控制。

### 已确认配置与实测结果

- 当前轮位为 B=FL、A=FR、D=RL、C=RR。
- 车辆前进的电气方向为：B/FL→ELEC_REV、A/FR→ELEC_REV、D/RL→ELEC_FWD、C/RR→ELEC_FWD；车辆后退使用相反电气方向。
- 车辆前进时编码器原始增量和逻辑符号为：B 原始为正、SIGN=+1；A 原始为负、SIGN=-1；D 原始为正、SIGN=+1；C 原始为负、SIGN=-1。
- 代表性原始增量为：B-FWD=-858、B-REV=+918；A-FWD=+1028、A-REV=-1027；C-FWD=-1045、C-REV=+990；D-FWD=+1015、D-REV=-1015。电气方向名称仅描述 IN1/IN2 组合，车辆物理方向以新车头观察结果为准。
- PWM=180/999（约 18%）时，四路均可连续转动；不存在 B 专用固定 PWM 补偿。旧工程中的 B 偏慢处理为四轮独立速度 PI 调节，不是 B 固定偏置。

### 软件与安全状态

- `NewFrontDirectionMap` 在 User 上层作为唯一方向/符号配置源，记录车辆方向到 ELEC_FWD/ELEC_REV 的映射及编码器逻辑符号；MotorDriver 底层电气定义保持不变。
- 保留 KEY1 选择 B/A/D/C、KEY2 切换 ELEC_FWD/ELEC_REV、WK_UP 长按 1000 ms 执行单轮测试的安全流程；每次仅一个通道、PWM=180、最长 800 ms，任意按键可中止并关闭 STY/STBY。
- ARM Compiler 5.06 编译结果为 0 Error(s)、0 Warning(s)，生成 AXF 和 HEX；程序已完成实机单轮验证。

### 后续边界

本阶段只确认单轮车辆前进方向与编码器逻辑符号。整车前进/后退/转向动作、左右轮速度分组、速度 PI 和灰度闭环控制仍须在后续独立阶段实现与验证。

### 最终结论

通过：新车头下四路单轮电气方向和编码器逻辑符号均已实测确认，可作为后续底盘方向重验的输入基线；不得将其直接等同于已完成整车控制验证。

每次准备提交和 push 前，检查本次修改所属阶段及问题状态，并同步更新本文件和《问题记录》。仅记录已确认的代码变化与硬件测试结果；未进行硬件测试时写明“仅编译通过，尚未完成硬件验证”。不删除有效历史记录，不把未来计划写成已完成，避免重复记录同一问题；文档更新应与本次代码一同提交。
