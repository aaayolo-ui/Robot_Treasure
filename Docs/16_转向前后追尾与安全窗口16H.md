# 16H 转向前后追尾与安全窗口

16H 复制自16G，独立工程为 `STM32/Keil_Project/Thief16H_TurnClearance_FourLaser_Test`。回放在 [16H页面](http://127.0.0.1:8765/variants/16h/replay.html)。原16E/16F/16G及其他已有文件保持原样，未提交、推送或烧录。

## 复现的问题

16G完整开局中，小偷从N038转移到N059，等警方从左侧检出后再沿N059→N060离开。N060仅有直角转向退路，停车旋转让警方沿直线追上。同速场景在28.532秒接触，发生在转完后刚离开路口；警方快20%的场景在25.764秒接触，发生在旋转末段。旧碰撞判定在这两场都正确判警方赢，问题出在藏点和路线选择。

N059虽然有三个不同的下一分岔方向，但其中一个前后出口需先连续拐弯才能抵达分岔。此前把它当成容易脱身的藏点，忽略了强制转弯期间的暴露。此前候选排序也把新旧藏点放在安全余量之前，可能放弃更安全的旧藏点。

## 最终改法

停车轴的前、后方向必须各自能先直达下一处分岔，期间无强制90度拐弯，仍排除死路、单入口口袋区和长直道藏点。当前合格候选为N011、N012、N038、N062；候选是更严格的拓扑筛选结果，并非证明任何来向都安全。初始取宝路线及第一藏点N038沿用16G，朝向由实际抵达路线完成。

每次规划以自己的节点、朝向、已确认激光距离和地图为输入。警方最快可达时间来自已见位置的道路传播，默认不扣警方转弯时间，不假设警方较慢。预测窗口从3秒扩至6秒。

转弯、制动换向的检查覆盖停车开始、旋转结束和沿新道路离开的前275毫米；离开阶段使用移动后的位置，没有额外虚构一段停车时间。每75毫米采样并保留120毫秒时间余量。一般行驶路段也继续检查风险。

规划车身接触余量从180毫米改为275毫米。它来自两辆名义190×198毫米车辆的半对角线之和向上取整，可覆盖旋转时扩大到车角的外包络。这只是保守选路用的圈包络，实际抓捕仍使用原16F连续旋转矩形的首次接触，没有缩车、免碰撞时间或转弯保护期。

候选排序先比较有无正时间余量。全部路线都存在保守风险时，优先推迟第一次危险转弯/停车，再比较新旧藏点、最小余量和路线质量。危险停留成本、短期朝已见来车方向行驶的成本，以及停车轴前后直行余量参与评分；地图推断的可能来向是辅助评分，不冒充新的激光观测。只有一条可执行退路时允许降级逃离，不能因为余量为负就停在警察面前。

前后转移仍使用已验证运动接口：首次从停车状态倒车不额外旋转180度；只沿原车身轴离开，不新增未经验证的起步原地90度转向。警方追击、丢失线索后的搜索，以及取宝不停留行为均保持原样。

## 参数和诊断

所有规划参数在新工程 `Algorithm/ThiefStrategy/ThiefStrategyConfig.h`；运动执行参数仍在 `User/App_ThiefStrategy.c`，本次未改变速度、转角、PID、PWM、制动或找线逻辑。

| 参数 | 当前值 | 含义 |
| --- | --- | --- |
| `THIEF_FORWARD_MM_S` / `THIEF_REVERSE_MM_S` | 674 / 679 mm/s | 沿用速度估计 |
| `THIEF_POLICE_MAX_MM_S` | 815 mm/s | 规划警方速度上界 |
| `THIEF_TURN_EXTRA_MS` | 768 ms | 沿用路口转弯额外代价，非纯旋转实测时间 |
| `THIEF_SWITCH_TO_REV_MS` / `THIEF_SWITCH_TO_FWD_MS` | 282 / 274 ms | 沿用行驶换向估计 |
| `THIEF_CONTACT_MM` / `THIEF_TURN_CLEAR_MM` | 275 / 275 mm | 规划包络和离开检查长度 |
| `THIEF_RISK_HORIZON_MS` | 6000 ms | 已见线索的短期预测窗口 |
| `THIEF_HIDE_REACTION_MS` | 340 ms | 到站停稳、确认、计算、起步的规划时间预算 |

## 模型对照结果

保持双方尺寸、地图、传感距离、运动参数、警方策略和连续矩形判据相同，使用种子10、11、12进行复核，每项为三场平均首次接触时间。

| 警方速度 | 16F | 16G | 16H |
| --- | --- | --- | --- |
| 同速 | 37.784 s | 28.532 s | 35.565 s |
| 快10% | 32.563 s | 27.023 s | 34.204 s |
| 快20% | 25.426 s | 25.762 s | 33.193 s |

三版本共27场均最终警方赢，没有规划失败。16H避开本次N059→N060的短距离转弯追尾陷阱，但仍会在后续途中或路口相遇被抓。相比16G，这三种速度的生存时间都有改善；同速时仍未超过16F，因此保留旧版供对比，不声称全面优于全部历史策略。

种子仅改变漏检随机序列，很多轨迹仍重合，这不是27次独立实车试验或胜率结论。另有七个展示场景，包括同轴近距追击和不同停车朝向的不利对照。N038同轴来车、N062被追到强制拐弯时，当前硬件动作和警戒距离可能已无安全退路，仍按实际矩形接触立即判抓捕。

开发中试过强制优先选择6秒内抵达的藏点，警方快20%场景提前到24.655秒被抓，已从最终代码撤回。早期评分消融的整场指标未变化，不能把整体增益归因于每一项新增权重；更严格的藏点筛选是本组场景的重要变化。开发记录与最终源码验证分开保存。

## 验证及实际边界

Keil ARMCC5全量编译：0 Error(s), 0 Warning(s)。Flash46,508字节、RAM35,784字节；算法工作区14,681字节，704状态静态上限，本次测试最大展开361状态，无堆分配或递归。

实际C算法11,170项检查、UART解析435项检查均0失败；转向前已无间隙、转向中失去余量、停车刚结束看似安全但离开时余量不足、有真实地图绕行时允许转弯等检查通过。连续碰撞与运动学18项测试通过，覆盖帧间相撞、转角扫到旁车、倒车保留车头方向等情况。

离线页面脚本检查节点/路段点击、开关、不同颜色轨迹、转弯角度、风险跳转和首次接触标记。88节点、106路段和原地图对应关系不变。117个硬件/控制/Core/系统/厂商文件与16G字节一致，6,418个此前已有文件的哈希未改变。PNG为报告坐标绘制的静态示意图，并非浏览器截图。

目前移动时激光接收仍沿用基线关闭方案；因此离开藏点后新出现的车、超过预测窗口的警察路线变化，以及定位误差仍可能导致碰撞。名义尺寸、激光安装偏移与测表面距离、制动滑行、找线位移和加速度尚未标定，不能据此承诺实车不追尾。板上规划是否满足100毫秒计算预算也需读取实车日志确认。
