## 2026-10-11 四方向激光扩展核对

本节为最新增量，优先于下方 2026-10-10 的恢复计划。用户已确认在现有前激光外增加三只同款 AI-1811，分别朝左、右、后；没有扩展板，只需考虑 TX。核对工程为 `Thief16A_FrontLaser_MapStrategy_Test`，并已检查用户提供的绿深系统板原理图。以下新增分配为改线计划，尚未修改固件或验证实物。

| 四方向改线计划 | 最终规划用途 | 必须先完成的迁移 |
|---|---|---|
| PA3 / USART2_RX | 前激光 TX | 保持现有连接，JP1 第11脚 |
| PB7 / USART1_RX 重映射 | 左激光 TX | 用户取消 TFT，先断开屏幕；激光接 JP3 第8脚 |
| PC11 / UART4_RX | 右激光 TX | 左前编码器 B 相从 PC11 移到 PB14；激光接 JP3 第15脚 |
| PB11 / USART3_RX | 后激光 TX | 断开蓝牙/USB转TTL的 TX；激光接 JP1 第19脚，PB10 日志发送保留 |
| PB15 | 暂不分配 | TFT 已取消，不再迁移 CS 到此；引出为 JP1 第25脚 |
| PB14 / EXTI14 输入 | 迁移后的左前编码器 B 相 | JP1 第26脚；移除旧红外输出，软件跨端口读取 PC10/PB14 |

下表为迁移前资源核对，不应与上述计划混同。

| 接收资源 | 当前占用 | 新增激光约束 |
|---|---|---|
| PA3 / USART2_RX | 前 AI-1811；用户已反馈接线；当前源码已有接收 | 保留前向；不得并接其他模块 TX |
| PB11 / USART3_RX | USB 转 TTL / 蓝牙接收 | 若改作激光，必须断开原外部 TX 并修改软件；PB10 日志发送可独立保留。只释放这一脚仍不足三路 |
| PD2 / UART5_RX | JY61P 姿态接收，源码 9600 | 保留陀螺仪 |
| PA10 / USART1_RX | 左后电机 D 的 IN2；板载 CH340G TXD（原理图 IC1 第2脚） | 撤销 PA10 激光候选；保持电机连接，不能并接激光 TX |
| PB7 / USART1_RX 重映射 | TFT CS | 禁止直接接激光；与 PA10 是同一串口，不能算两路 |
| PC11 / UART4_RX | 左前编码器 B 相 | 禁止直接接激光；USART3 部分重映射到此也不会增加独立通道 |

结论：通过取消 TFT、迁移左前编码器 B 相、释放 PB11 日志接收，可形成四路独立硬件 UART RX，无需扩展板。PB14 用于迁移编码器，PB15 暂不分配，不直接接激光 TX。PB10 保留电脑/蓝牙日志输出，车载蓝牙 RX 接 PB10、TX 留空。接线和新固件必须配套，详情见 [05_四方向激光扩展接线规划.md](05_四方向激光扩展接线规划.md)。

当前源码已配置 UART5 和 USART2，不能再将其描述为尚未接入软件。特别注意：小偷工程移动期间关闭 USART2，停稳躲藏后恢复；接上四只传感器不会自动获得四方向连续检测。该行为来自现有代码，不代表已验证四路方案。

## 当前空闲 / 未分配

上表之外的引脚不能直接视为可用。它们可能未在当前 `.ioc` 配置，却仍可能受板载 TFT、开发板排针未引出、晶振、下载接口或复用限制影响。对这类引脚的唯一可用表述是：**未在当前 `.ioc` 占用，但开发板板载连接和实际引出状态待原理图确认。** 新功能应先确认开发板原理图、实体引出和复用冲突，再更新 `.ioc`、驱动与本表。
