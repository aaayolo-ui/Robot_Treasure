## 四激光、蓝牙与姿态信号

| 模块端 | MCU 信号 | 排针（原理图） | 必查项目 |
|---|---|---|---|
| 前激光 T/TX | PA3 / USART2_RX | JP1 第11脚 | 不能接到相邻 PA2；FrontUartOff 对照版软件保持此前向接收关闭 |
| 左激光 T/TX | PB7 / USART1_RX 重映射 | JP3 第10脚 | TFT 物理断开；不能残留旧编码器或其他输出 |
| 右激光 T/TX | PC11 / UART4_RX | JP3 第15脚 | 旧左前编码器 B 相必须已移走 |
| 后激光 T/TX | PB11 / USART3_RX | JP1 第21脚 | 车载蓝牙 TX、外置 USB-TTL TX 不得同时接此处 |
| 车载蓝牙 RX | PB10 / USART3_TX | JP1 第22脚 | 只接收车上日志；车载蓝牙 TX 留空并绝缘 |
| JY61P TX | PD2 / UART5_RX | JP3 第13脚 | 保持现有姿态输入 |
| JY61P RX | PC12 / UART5_TX | JP3 第16脚 | 不得误与 PC11 共接 |

四只激光的 R/RX 均保持不接、单独绝缘。PA2 当前专用于电机 D 的 PWM，不能接前激光 R/RX、蓝牙信号或其他负载。电脑端串口链路仍为：车载 PB10 → 车载蓝牙 RX → 无线 → 电脑蓝牙 TX → USB-TTL RX → COM13；各段按现有已确认电源和 GND 连接。

PB11 的限制指外置日志设备的 TX；系统板自带 CH340 是另一组 PA9/PA10 信号，不能混为一谈。

## 电机及编码器对照表

| 驱动通道 / 当前轮位 | PWM | IN1 | IN2 | 编码器 A 相 | 编码器 B 相 |
|---|---|---|---|---|---|
| A / 右前 | PC6 | PC0 | PC1 | PA6 | PA7 |
| B / 左前 | PC7 | PC3 | PC4 | PC10 | PB14 |
| C / 右后 | PA1 | PC5 | PB0 | PA15 | PB3 |
| D / 左后 | PA2 | PB1 | PA10 | PA8 | PA9 |

公共 STY/STBY 为 PC2。电机动力端和编码器 AB 信号端分别核对，不凭电机线或六芯插头颜色调整极性。前进电气方向由 `NewFrontDriveMap.c` 定义，不能只按电机通道字母猜测。

重点检查：

1. 右后 C 的 PWM 是 PA1（JP1 第9脚），不是 PA2（JP1 第12脚）；C 的 IN1/IN2 分别为 PC5（JP1 第17脚）、PB0（JP1 第20脚）。
2. 左前编码器两相为 PC10/PB14。PC11 已用于右激光；PB14 不能还接旧红外 OUT；更早的 PB6/PB7 编码器接法不适用于此工程。
3. TFT 的 PB7/CS 物理连接应已解除。只停用显示函数不等于断开屏幕负载。
4. C 轮已在上次 PWM=0、STBY=0 的手转窗口中确认对应 C 编码器；这不能证明其全部线束和激光启用后的信号都正常。

## 板载 CH340 与 PA10 共线

原理图 IC1/CH340G 第2脚 TXD 直接接 PA10，第3脚 RXD 接 PA9；图中 CH340 VCC 接公共 5V，未画出 PA10 串接隔离跳帽。当前程序把 PA10 配为电机 D 的 IN2 推挽输出，而 PA9 为 D 编码器输入。

2026-10-16 用户补充确认 PA10 接驱动板 DIN2，并提供开发板正面照片。照片可见 V2.0 丝印，左下方、左侧 USB 插座上方的 IC1 标为 WCH CH340C；与旧原理图标注的 CH340G 型号不同。该结论是照片识别，不是电气连通测量。

照片另可见 JC1/JC2 位置的标“0”器件，旧原理图没有对应标号。目前无法仅据正面照片确认它们是否串接在 PA9/PA10 与 CH340 之间，不指定拆除其中任何一个。需要断电通断测量或与实物版本一致的资料，才能确定实际连接和隔离方案。

因此需要确认实物板是否与该图相同、CH340 TXD 是否已隔离，以及这条线上是否存在另一个驱动输出。仅不打开串口、或仅拔掉电脑 USB 线，不足以从这张原理图证明 CH340 已与 PA10 隔离。该共线是需核实的结构性风险，不能仅据原理图认定它导致了本次取宝后故障；本次不要求割线、拆芯片、改焊或更换引脚。

## 本次故障的排查优先级

如果此前同一板卡、同样 PA10 接线能够正常运行，板载 CH340 的存在本身不能解释为何修改小偷工程后才出现异常。PA10 与 CH340 TXD 的低阻连通现已按用户测量反馈确认，其与本次故障的因果关系仍待核实，不单据共线认定根因，也不要求先拆除芯片或 JC1/JC2。

2026-10-16 重新对比源码：全图标定工程 main.c 只初始化 USART3/UART5；仓库旧版 16B（c15d11b）的 Route_Start 调用 LaserRx_SetEnabled(0U)，停稳进入 HIDING 后才恢复接收；当前小偷工程改为经过 N005 时在移动中启用激光，并在后续转移中保持接收。旧版源码对比不等于已核定用户当时烧录的二进制版本。

现有实车证据中，PA2 数字读回异常紧随激光启用出现，优先验证已烧录的 FrontUartOff 单变量对照：保持原接线与运动控制，仅让前激光 USART2 继续关闭，观察 PA2 及四轮行为是否恢复。对照结果尚未收到，不能提前宣布原因或修复成功。

## 断电检查顺序

1. 先停止采集并断开车辆电源及可能反向供电的连接，保持电机不运行；需要确认断电后再插拔。
2. 优先核对后激光实际接 PB11（JP1 第21脚）还是误接 PB1（JP1 第19脚），再核对左激光 PB7（JP3 第10脚）。有不一致先记录并确认实物板型，不盲目搬线。
3. 检查蓝牙 TX 是否仍连 PB11，TFT 是否仍接 PB7，编码器是否残留 PC11/PB7/PB14 的旧接线，激光 R 是否误接 PA2。
4. 逐根核对 C/D 的 PWM、IN1、IN2 和编码器线两端标签；检查相邻排针跨接、松动及插头退针。万用表通断只能在完全断电后使用，不能凭在板蜂鸣就判定没有其他负载。
5. 核实 PA10 与板载 CH340 的隔离状态。未确认时先提供板卡信息和现场接线，不改变供电、极性或板载走线。
6. 接线确认后再人工复位，在 PWM=0、STBY=0 状态检查串口和编码器；路线试跑另行人工启动，不能由电脑自动发运行命令。

上次 WheelSignal 日志记录的直接异常是激光启用后 PA2 数字读回与预期 PWM 不符；实物 C 轮现象与 D 通道异常应分别检查。数字读回不是驱动板端的示波器测量，不能直接判电机或驱动板损坏。FrontUartOff 仍是单变量原因对照，不能把停用前激光等同于完整四激光策略已修复。
