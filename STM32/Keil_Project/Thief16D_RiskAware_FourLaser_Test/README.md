# Thief16D STM32 风险感知小偷策略

从 `Thief16B_FourLaser_MapStrategy_Test` 独立复制；原16A、16B、16C及电脑回放策略保留。无需虚拟机、服务器、联网或训练模型。电脑只负责离线拓扑生成、编译和测试，决策在STM32本机执行。

仅编译通过，尚未完成硬件验证。

## 打开工程

[Keil工程](MDK-ARM/Thief16D_RiskAware_FourLaser_Test.uvprojx)。MCU、时钟、Flash下载设置沿用16B；未烧录、未自动驱动电机。用户短按KEY2开始；运行时按KEY1/WK_UP/KEY2按原逻辑制动停止。起点N054，车头朝西。

## 新策略做什么

1. 固定取宝前缀不变：N054→N053右转→N044直行→N036左转→N035/N034直行→N033右转→N025/N015直行→N006左转→N005宝藏→N004。宝藏直穿不停车。
2. 首藏点不再固定N059。根据藏点退路、直道跨度、附近路口、警方从出生点到可检测位置的预计时间以及自己的行驶耗时选择。当前地图和默认参数选择N023：取宝后N004→N003→N013→N012→N023。
3. 到藏点停稳后四方向检测。稳定的合法道路目标更新地图内物体的可能位置；未检测到对手的地方不会凭全局回放数据加入模型。
4. 逃跑时使用88节点×4行进朝向×2正倒车状态的时间搜索。首段必须避开所有当前检出方向，并能直接前进/倒车离开；路径不能立即沿刚走过的边折返。
5. 根据最近测距命中位置、已过去时间及假定的对手最大速度，计算对手到达各节点/路段位置的最早时间。检查转向等待及移动中的交会风险，然后比较下一个藏点的质量和预计耗时，取消旧“接近1.5m”的目标评分。
6. 当前暴露藏点禁用30秒；到下个藏点等待新检测，保持完整路线承诺，不在移动中反复推翻路线。

藏点先在电脑上筛选，烧入ROM。排除死路、单出口环路及其入口、跨度大于900mm的整条直道。由于当前控制器从藏点只支持直接前进/倒车起步，停靠轴两端都必须接入可靠环路，不能将通向死路的分支算作退路。当前候选：N023、N039、N044、N059、N062、N063；到达朝向不合适时也不会选择该点。

## 算法的准确边界

这是有限状态时间寻路＋对手可达区域＋短期风险评分，不是完整SIPP、概率POMDP或全局最优博弈求解。每个状态仅保存一个代价标签，可能舍弃更好路线；交会检查沿路段每不超过75mm采样，考虑接触范围与时间余量，不提供连续运动的防撞证明。

已知威胁下优先选前三秒内有正余量的路线。如果没有这样的完整路线，但首段仍通过严格筛选，则选择最小风险路线并输出 `DEGRADED=1`；它可能被抓到。首段也没有可用路线时保持制动并报 `ESCAPE_PLAN_FAILED`，不盲目冲向物体。

保留16B的移动期串口隔离：取宝和逃跑时关闭激光接收，仅停稳后启用。所以本版没有行驶中新检测后的即时避碰；途中只能使用出发时得到的线索。最近观测保存4秒，不会永久当作已知对手位置。单点激光识别的是物体，不能区分车和人。

原路口识别和坐标更新控制没有重写。实际路口误认、漏认、打滑或转向不到位仍可能使规划在错误位置执行，应从节点/里程日志验证，不应以规划测试通过当作实车路径正确。

TFT断开，软件无屏幕驱动；VCC/GND按用户既定接法，本版只修改策略。电机映射、PI/PID、速度和转向控制参数从16B复制保留。

## STM32资源与计算预算

- 按Keil原有48KiB RAM、256KiB Flash配置核对，最终构建大小见VERIFICATION.md。
- 搜索最多704轮，没有递归、动态内存分配或依赖Python；拓扑表在ROM，搜索工作区13265字节。
- 仅停车时规划；移动周期不进行规划，也不格式化四激光状态日志。
- 逃跑规划计算超过100ms则保持制动，输出 `PLANNING_BUDGET_EXCEEDED`。真实板上耗时需查看 `COMPUTE_MS`，电脑CPU模拟不代表72MHz板上的耗时。
- 新工程栈增为2KiB；链接器静态调用图存在间接调用的未知部分，仍需实车核对中断与栈余量。

## 参数位置

规划参数集中于 `Algorithm/ThiefStrategy/ThiefStrategyConfig.h`：前进674mm/s、倒车679mm/s、警方最大速度假设815mm/s、90°额外代价768ms、前进换倒车282ms、倒车换前进274ms。来自旧标定估计/建模假设，不是本次新增实测；当前电机调速或转角改变后，应重新标定。警方上限必须覆盖真实最快速度，设得过低会漏判风险。

修改地图或规划耗时参数后，在电脑重新执行 `python Tests/generate_topology.py`，再编译。控制器实际旋转阈值仍沿用基线45°，规划的“90°额外代价”与实际旋转终止阈值不同；它代表完整拐角动作的估计耗时，需实测修正。

## 串口与验证

电脑接收115200、8N1、文本。开机和每次逃跑输出 `PLAN_V2`：目标、预计路线耗时、最小交会时间余量、展开状态数、有效威胁数、是否退化选择。逃跑另输出 `COMPUTE_MS`。`MARGIN_MS` 是模型余量，不是实测安全时间；无有效威胁时的6000是哨兵值。四方向 `LASER` 日志沿用16B，仅停止时格式化输出。
