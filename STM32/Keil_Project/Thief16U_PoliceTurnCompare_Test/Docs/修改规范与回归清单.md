# 修改规范与回归清单

## 每次改代码前必读：防遗漏核对表

入口只校验一次，拒绝重复判空和滥用try /catch，单次逻辑不乱抽函数，低概率防御先征求同意。

每次修改源码、控制参数、传感器配置或状态机（包括同一轮后续修改）前，重新读取本节、当前版本章节、README和最新有关日志；按改动影响逐项记录“已覆盖/不适用/尚未验证”，不得只修出现问题的一个节点。

1. **先列完整调用路径。** 区分正常到口转弯、藏点/路口重新出发、半路拦截折返、出口找线、道路失线恢复。检查所有调用者和状态入口，尤其departure_turn使用的虚拟起步动作与路线第一步终点动作不同，不能用错step。
2. **转弯必须查全地图。** 共用转弯逻辑，不写只覆盖N004/N006而遗漏N078的节点名单。依据实际MapRoutePlan拓扑枚举合法左右转弯、正反行驶、两种陀螺仪符号；单独验证根节点重新出发与首次未知符号。没有道路的方向不得因“反方向逃跑”而直冲（例如N078到N087没有直接道路）。
3. **区分角度、转动停止和在线位置。** 原始YAW不等于地图误差，日志角度单位x100，YAW误差为0也不证明车在线中央。目标用出口地图轴，不能把入弯偏斜的统计均值直接当固定旋转角。按MONITOR12用户选择，普通转弯只做一次实测消余转制动和新鲜YAW交接，不逐次驻车修到±2度或等3帧角度；随后实际灰度决定巡线/找线，小偏差交PID。检查正负180度、过冲、未知符号首次粗转与累计转角边界。
4. **检查控制链真的接上。** 制动会关闭轮速PI；进入FOLLOW只在IsEnabled实际为真时允许保留，否则重新启用。验证全四轮目标、控制器使能、PI到PWM输出，不能只看STATE=FOLLOW或目标非零；测试不得把这些控制层全部模拟掉后宣称能走。5ms灰度观察不得重复支付20ms轮速积分。
5. **地图方向不等于固定探头。** 上/右/下/左是世界N/E/S/W；前/左/右/后探头固定在车身，按body_heading换算。倒车时TravelFrame、领先/跟随灰度板、转向符号和物理车头分开核对。边界射线过滤、传感器偏置和800/1000mm有效距离规则不能被路线修改覆盖。
6. **规划和执行都要覆盖避障。** N011下方来车优先N012-N013，上方来车优先N010；优先出口/第二段已有堵路或该出口也有即时威胁时回退普通合法路线。约束用完必须复位，不能泄漏到N038等其他节点。行驶中实际激光拦截仍优先回撤/重算，不能为履行旧路线继续硬闯。
7. **道路身份与航向门槛分开。** 超±10度不能直接等于道路上下文消失；可在已提交道路上继续航向恢复，不能放宽真正出口/节点确认条件。检查连续双板无线2秒在阶段切换中不被重置，有真实线时不累计分散的无线间隔；不能又增加固定纠偏总时限直接停车。
8. **定位证据不能混用。** 编码器仅辅助，不凭里程直接认节点；半路折返保留已走位移的有符号账本。迟到相似路口需候选与真实后续观测，不把上一轮残留灰度、单帧全黑或显示预测当确认。入中心动作仍用原100RPM/180ms及已走位移抵扣；不为掩盖问题降低用户认可的正常速度。
9. **回归入口必须真实。** 更新状态机后，旧用例应先实际完成新增前置阶段再复现后续扰动；禁止强设成功标志、虚构传感器、删除失线/停稳/新YAW断言来让测试通过。用户明确改变规则时，保留旧脚本并说明新预期；覆盖范围、实际执行的源码/AXF散列和未测试硬件必须写清。
10. **交付之前核对一致性。** 保留修改前工程/AXF/日志及失败复现；更新当前版本、README、AGENTS、差异与验证报告。只在新改动或失败有理由时重跑相应检查。不得自动烧录、驱动实物、占用串口、提交或推送。编译/仿真不能冒充实车证明。

## 每次修改的执行顺序

1. 确认准确工程路径、读取本规范与README、检查Git状态（无Git元数据就如实记录）、核对当前FW标识和源码。备份将修改的文件、原AXF、原日志及源文件散列。
2. 从日志确定触发状态、时刻、原始灰度、YAW、里程及最后故障。区分缓冲回放与当前动作，不能把故障后输出的旧TW记录当作仍在驱动。
3. 为新问题先写最小复现用例，验证原版确实在该断言失败。保存失败记录与复现脚本，不能把无效路线、错误长度或测试装置错误算成原固件缺陷。
4. 只修相关状态机/控制模块。控制算法放Control/Algorithm，应用只调度，main.c和底层硬件不扩散业务。不得用删除全部故障处理、伪造灰度、伪造节点位置来使测试通过。
5. ARMCC5全量编译，并运行新用例及受影响旧回归。模拟车辆模型必须对新增旋转/制动命令作出相应输入反馈；模型也不能直接把目标姿态强行写成已确认状态。
6. 核对每份结果的AXF、源码、测试脚本及依赖脚本SHA-256；改变固件后旧的应用结果必须重跑。纯算法未改动时可保留源码散列相符的独立算法结果。
7. 更新README、增量差异、验证报告和本清单状态。明确区分编译、离线、实车验证；由用户决定烧录与实车运行。
