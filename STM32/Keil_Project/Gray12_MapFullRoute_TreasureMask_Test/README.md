# 全图宝藏区文字过滤版

从 `Gray12_MapFullRoute_Calibration_Test` 当前文件独立复制。用户实车发现 N004 与 N006 之间的“宝藏区”文字触发边缘灰度，造成循迹纠偏偏离；本版针对这段路增加北侧最外两路过滤。

## 打开与启动

- Keil：`MDK-ARM/Gray12_MapFullRoute_TreasureMask_Test.uvprojx`。
- HEX：`MDK-ARM/Gray12_MapFullRoute_TreasureMask_Test/Gray12_MapFullRoute_TreasureMask_Test.hex`。
- 起点 N081，车头朝地图上方；短按 KEY2 启动。
- 运行中 KEY1、WK_UP、KEY2 停车。启动串口标识含 `TreasureMask_Test MT3 MASK1`，可确认烧录版本。
- 仍是原来的 210 步全图路线；N005 是 N004—N006 路段内点，不增加停车或转弯。

## 过滤规则

文字侧按地图北侧处理，沿用原工程已记录的前后板安装关系。

| 地理行驶方向 | 逻辑领头灰度屏蔽 | 逻辑尾随灰度屏蔽 |
| --- | --- | --- |
| N004 → N006，向东 | P11/P12（0xC00） | P1/P2（0x003） |
| N006 → N004，向西 | P1/P2（0x003） | P11/P12（0xC00） |

前进时前板领头、后板尾随；倒车时后板领头、前板尾随。因此不能固定屏蔽同一块板的同一侧。物理接线不变。

在提取 12 位读数之后、计算灰度位置之前，将对应两位清零，其余十路照常参与控制。位置 PID、双灰度航向修正、侧边增益和误差减速都使用过滤后的数据。路口分类也使用过滤后的数据，避免文字触发假北侧分支；N004/N006 的真实南侧分支保留。此段相关日志中的 RAW12 是过滤后的读数。

只有当前导航路段是 N004↔N006，且处于 FOLLOW、LEAVE_START、MAP_PASS 或 FRONT_RECOVERY 时启用；旋转、转后找线和其他路段不屏蔽。仅检测到被屏蔽文字而其余十路全白时，仍返回丢线，不伪造居中黑线。

生效边界沿用导航状态中的当前路段，不是精确测得两块板的物理过界位置。若文字还影响 P3/P10 等内侧通道，本版不会将它们屏蔽，需要实测后另行判断。
