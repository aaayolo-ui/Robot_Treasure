# 16M UART-CH4：五藏点、途中拦截回撤

由同级 `Thief16B_UARTCh4_MapStrategy_Test` 复制，原工程保留。
打开 `MDK-ARM/Thief16M_UARTCh4_InterceptEscape_Test.uvprojx`。
启动标识：`FW=UARTCH4_16M_RUN1 ALGO=16M`。

## 策略

- 原始测距有效上限 **1000 mm**。依据用户给出的“1000 对应实际约 900 mm”，
  地图投影暂用原始值乘 **0.9**；日志保留原始值。这是单点比例估计，尚非全量程实测标定。
- 藏点固定为 **N011 横、N038 横、N026 竖、N035 横、N063 竖**。
  横允许朝东/西，竖允许朝南/北；到达方向由路径搜索一并决定。
- 保留 N054 朝 N053 的起步方向与既有取宝前缀。通过 N005 后才启用运行检测；
  首藏点仍为 N038 横。
- 遇到物体后，优先比较路径风险等级，再优先选离最近记忆物体更远的藏点，
  最后比较藏点复用与包含转弯、换向、威胁惩罚的路径代价。距离按曼哈顿距离、300 mm 分档。
  实时搜索地图，不按固定藏点顺序循环，也不使用旧 Rollout 的预生成路线。
- 运动中前方/侧向出现有效检测：**优先刹车，轮速确认停稳后，沿当前线回撤**。
  回到上一灰度确认路口后重新规划。回撤保持车头方向，切换前后循迹和轮速映射，
  不把尚未到达的路口伪造成定位点。
- 回撤终点只是重新规划点，可以不是五个藏点之一；它不会被当作长期藏点。
  回撤途中再次遭拦截也可换向，350 ms 冷却避免连续来回抖动。被拦截路段记录 4 秒，
  有其他路时优先避开。
- 仅后方有物体时继续远离；前后都堵时，反向已知余量多出 200 mm 才换向，否则继续到路口选路。
  所有出口受威胁时，将禁行约束降为高额代价，选择风险较低的出口继续运动，
  用 `DEGRADED=1` 明示没有安全保证。
- 重新规划后可在路口侧向转弯。沿入路方向（包含倒车）执行原有 180 ms / 100 RPM 进位，
  刹停后切换新路线行驶模式，再完成陀螺仪与灰度确认的转向。
- 到五个正式藏点时，识别到路口后也沿当前行驶方向以 **100 RPM 再走 180 ms**，
  再刹车停稳；时间和速度直接复用转弯前的进位参数。已完成进位的藏点再次侧向出发时，
  不重复进位。拦截回撤的临时重新规划点仍立即刹停。
- 地图边缘只忽略朝场外的射线，朝场内的检测仍有效；图外或不能沿连续道路投影的返回值也忽略。
  此判断依据几何位置，不能识别人、墙或小车的身份。

## 已精简的误停车逻辑

- 规划已在停车状态执行且迭代有界：超过 100 ms 只记录 `PLAN_SLOW`，不再永久退出策略。
- 直行过路口时一次灰度通信失败/暂时无黑线，复用 200 ms 短暂恢复流程，不再立即永久停车。
- 拦截回撤切换前后灰度后，首个读数偶发无效也进入同一恢复流程，持续无效才停车。

人工停车、换向前实际停稳、持续失线、陀螺仪失效、定位矛盾等保护仍有效。
“立即回撤”指有效检测确认后优先刹车，不是高速中直接反接电机。
高质量信号使用同一传感器连续两帧确认；低质量信号保留五帧稳定判定。
运动帧须在 25 ms 内且航向误差不超过 5°；转弯/路口过渡尚无有效朝向时不投影新威胁。

## 验证和使用边界

接线、电机映射、编码器、陀螺仪、UART-CH4、PID 沿用父工程。KEY2 启动、KEY1 停车。
本次不自动烧录、不连接串口、不运行实物电机。

- `build_16M.log`：该工程 ARMCC5 全量编译记录。
- `Tests/results_16m.json`：实际算法/定位 C 代码的 Cortex-M3 离线检查。
- `Tests/results_app_runtime.json`：已链接固件中的真实应用函数测试；硬件调用用测试桩替代。
- `VALIDATION_16M.json`：文件差异、底层一致性、工程路径、测试与产物摘要。
- `SOURCE_CHANGESET.patch`：与原工程相比的文本差异。该下载目录没有 `.git`。

复验：`python Tests/run_16m.py`、`python Tests/test_app_runtime.py`、
`python Tests/verify_snapshot.py`。依赖位于 `Tests/build/deps`。

**仅编译通过，尚未完成硬件验证**。离线检查通过不能代替取宝、回撤、定位和对抗实测。
路径优劣基于地图、估计速度和观测；不保证在未知对手动作、漏检、打滑或实际包围下不被抓。

策略参数位于 `Algorithm/ThiefStrategy/ThiefStrategyConfig.h`，五个藏点轴向位于
`Algorithm/ThiefStrategy/ThiefInterceptPolicy.c`。逐项修改清单见 `VALIDATION_16M.json`。
