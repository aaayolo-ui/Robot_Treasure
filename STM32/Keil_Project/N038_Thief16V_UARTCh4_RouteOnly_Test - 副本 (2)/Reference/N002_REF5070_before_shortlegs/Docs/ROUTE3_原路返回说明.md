# ROUTE3原路返回说明

## 运行过程

例如N011西侧触发后走11-12-23-31-32-48-49-61-62-63。在31至32之间迎面遇阻，停止后先逆向巡线到31，再按31-23-12-11返回。23是途经直行路口；31、12按实际返回出口完成转向。不会把尚未走到的32/48等未来节点写入返回历史。

## 看日志

- TRACE_BEGIN HOME=N11 BODY=1：新一趟藏点转移开始，记录原藏点与停车轴。
- TRACE_STAGE N=12 RETURN=0：灰度识别到12，动作尚未作为完成提交。
- TRACE_COMMIT N=12 COUNT=1 RETURN_LEFT=0：完成动作并接线后记录第一条已执行边。
- TRACE_RETURN HOME=N11 FIRST=N31 STEPS=4 PARTIAL_MM=137：制动后本段已走137mm，先退到31，再逆序回家。FIRST是最近已知路口，可能是直行路口；回程会继续通过它到最近转弯点。
- TRACE_STAGE ... RETURN=1及TRACE_COMMIT ... RETURN_LEFT=...：返程确认和剩余路段数。
- TRACE_HOME N=11 LEFT=0 WAIT=FRESH_THREAT：返回完成，旧威胁清除，仍须原停车阶段确认。
- TRACE_HOME_CANCEL：确认尚未离开原藏点，没有执行虚拟整段回退。
- TRACE_STAGE_UNAVAILABLE：历史无法保持连接或容量不足，本趟不能保证历史回放；原退至路口规划仍在。
- TRACE_ABORT_FRONT：返回方向又被真正挡住，停止历史回放，使用基线退至路口重规划。

MT3/LOC仍是路线估计。部分折返首段的from/to是完整地图边的表示，实际位置还必须结合PARTIAL_MM和折返信用；不能把from编号单独当成实物正好在该节点。

## 验证范围

新增测试执行实际AXF，车辆和传感器为合成输入。覆盖16条完整生命周期（含原五藏点、不同入点轴向、两种YAW符号、跨±180度、10/44/120mm折返、多路口返回）、47条历史+部分路段的48步容量、错误侧线、回程转弯无线/旧后板线、17mm制动滑移、直行路口60mm继承、新前方堵路退出、按键及连续双白2秒停止。旧ROUTE2的N011前方忽略在相同前方探头用例中复现，并保留旧AXF散列。

16条完整转移的期望节点、实际回放目标和返回停车姿态在Tests/results_trace_return.json。其他边界在Tests/results_trace_recovery.json。全部当前报告必须绑定本次AXF；不能用旧日志的通过结论代替当前证据。

实际惯性、轮滑、灰度安装偏差、探头假回波、四轮静摩擦和最坏控制周期尚未实车测量。仅编译通过，尚未完成硬件验证。
