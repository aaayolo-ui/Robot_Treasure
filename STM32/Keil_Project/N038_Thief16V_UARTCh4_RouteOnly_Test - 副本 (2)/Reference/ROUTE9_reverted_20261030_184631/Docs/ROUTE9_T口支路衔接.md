# ROUTE9：居中T口的转弯前确认

当前固件UARTCH4_16V_ROUTE9_T_EXIT_SL1，工程路径保持。修改基础是ROUTE6_SL1；没有恢复已撤销的ROUTE7连续逃跑和ROUTE8近远路线修改。完整修改前快照Reference/ROUTE6_SL1_before_t_junction，458项散列可核查。

## 现场与证据边界

用户说明实际进路N006→N007→N017→N026→N035，正停在N035，北侧灰度中间两位识线、南侧灰度白底。从北向南进入此T口时，行进前端可能已越过横线，而后端仍在入弯竖线上；车头朝向不能仅凭地图箭头推断，因此不预设实物一定前进或倒车。

181239日志的故障事件T=62071ms，来自TURN_STOP，原因MAP_REQUIRED_BRANCH_NOT_SEEN；当时保存的060/0E0灰度缓存已旧460ms。网页9F7/BFF明确是600多秒前旧采样。日志没有完整该路口原始序列，不能据此断言哪个灯何时漏读；新测试依据用户现场状态构造模拟序列。

代码确认到达处理会清seen_ports，且到达前监听没有统一累计证据；原刹车后流程仅根据是否累计到指定侧最外两位决定能否转弯，无法接受正确居中后的前白后线组合。此次修证据生命周期并增加由真实T口线形支持的衔接。

## 实现与每次修改前必查

- 每次先读README、AGENTS、修改规范与回归清单。巡线优先；不能为策略或缺支路位而强制认定位置、盲冲或提前推进节点。
- 原5ms监听在已武装、未到达/锁存且符合原到达窗口时累计侧支路。MapRouteNavigator_Arrive保留本段记录；Start/Advance、Route_MapBeginLeg、重新武装清理，防止跨路段和恢复重进遗留。
- 原正常支路确认通过时完全走原流程。缺指定侧时，必须已到达并有其他侧支路证据；地图节点度3，沿入弯方向没有直路而左右均有路；当前行进前端为真实无线，后端读数新采集且为紧凑线，灰度误差±150以内。还要求有效方向符号、新鲜YAW、相对入弯身体方向在原±10度内，连续2个控制周期。
- 以上只允许启动原计划方向的普通转弯，不写入未观测的seen_ports、不提交历史边、不标记定位成功。四轮停稳与制动后新YAW帧仍由原流程判定。前端/后端是TravelFrame行进坐标，倒车时原映射继续负责选板，不能二次反转。
- 其他缺证情况仍保留原MAP_REQUIRED_BRANCH_NOT_SEEN，不把地图当成无条件转弯依据。交叉口、角点、双白、后板宽黑或偏离中心、未知方向符号、过期/偏航YAW均不能使用此T口衔接。原回程到达方向筛选门槛保持，未到达T口不能借本分支跳过该门槛。
- 不修改正常PID、平滑、巡线速度、180ms/100RPM入路口、45度主旋转及灰度接线，不添加角度精调或新的平移找线。不修改路线策略、激光量程/收发、引脚、Keil或PA3持续声光。

## 新日志

成功采用T口线形衔接时仅在将开始旋转的周期输出一次TURN_T_CENTER，含N、MODE、当次前后灰度RAW、原支路位SEEN和原动作ACTION。

支路仍不通过时输出TURN_BRANCH_MISSING，含FROM、AT、NEXT、MODE、SEEN、实时LEAD、T_COUNT，再进入原故障。这些记录有助于区分实际来路、控制方向和灰度证据；历史网页采样仍不能代替实时记录。
