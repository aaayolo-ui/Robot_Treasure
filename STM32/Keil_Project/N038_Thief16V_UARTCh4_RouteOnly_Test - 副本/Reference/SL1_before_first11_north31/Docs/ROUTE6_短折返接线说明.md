# ROUTE6_SHORT_RETURN：短距离折返接线修复（本段优先）

当前固件UARTCH4_16V_ROUTE6_SHORT_RETURN，工程仍为MDK-ARM/Thief16V_UARTCh4_RouteOnly_Test.uvprojx。ROUTE5修改前源文件、文档、测试证据及映像已备份Reference/ROUTE5_before_short_return，420项散列已核对。用户152637日志显示，从N007朝N017仅行驶89mm就遇敌折返，前后灰度仍偏斜时过早恢复前进，造成反复进退；场外北侧回波实际已经被忽略。

每次修改前继续读README、AGENTS及Docs/修改规范与回归清单。新增必查：

1. 后板带领退回时，前板重新有线不等于车身已顺线。前板可用后，将前后误差之差加入反向灰度纠偏；两板均为紧凑线，各误差在±150且误差差在±100以内，连续3次后才进入制动。这些是灰度通道位置单位，不是角度或毫米，不依赖假定安装距离。
2. 新HANDOFF阶段PH=5在实测停稳后再次检查两板。计划退回时，即便前板在刹车期间提前读到线，也不能绕过该条件。读数变差回到原恢复流程，不能强设定位成功。
3. 恢复交回原PID以当前50RPM作为平滑起点，再由原平滑逻辑提速，不恢复失线前保存的高速值。正常巡线速度及PID参数不变；没有新增每个转弯的地图航向微调。
4. 恢复不提交虚拟N017、不清里程锚点、不交换当前TravelFrame；真实路口与历史记录继续按原流程推进。正常转弯、180ms入路口、策略路线、激光前后1000/左右900mm和场外过滤不变。双板无线2秒、按键及真实硬件故障停车保留。

最终ARMCC5全量构建0错误、0警告；当前15组ARM离线回归全部通过。短折返专项包含六次完整模拟返回N038竖停，旧ROUTE5在同一专项失败已留证。ROM68096字节、RAM44888字节（较ROUTE5减少8）、剩余4264字节；3KB预留栈，链接器已知最大920字节，中断叠加及实际栈水位未测。AXF SHA256=4425b1de8734d6ffd2ac25e6dfd5d7849c65b60081962331b8a69e1d17cb5d5d。

## 复现和修复范围

152637日志主控23.897～26.908秒反复进入FRONT_WAIT、BACKTRACK及FOLLOW。灰度040/100、060/180、078/180中前板虽有线，两板读数仍不一致。旧版BACKTRACK一见前板有线就制动，再仅凭前板连续有效交回FOLLOW，并恢复失线前的速度。新前板在制动期间重现还可能绕过退回交接条件。

该日志随后确认N007左转，35.305秒回到N038进入HIDING，没有故障停车。N017是反向部分路段的虚拟起点，不代表实际到过。这里修复确认存在的恢复交接行为，不宣称已经确定最初失线的机械原因。

生产源只修改Control/RestartLineSearch.c与User/App_ThiefStrategy.c：前后板共同参与退回反馈、稳定后制动与HANDOFF检查、恢复速度接入原PID，并删除已无用途的保存速度变量。没有N007/N017专用电机动作，也没有按地图坐标盲走或固定距离盲退。
