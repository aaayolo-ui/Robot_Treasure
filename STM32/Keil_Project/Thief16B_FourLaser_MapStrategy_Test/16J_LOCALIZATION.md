# 16B直接接入16J与灰度/陀螺定位

日期：2026-10-13。按用户要求直接修改本16B工程，工程名称和接线保持16B。此前版本已保存在Git提交`c15d11b9ed7382862fe2c03c15bd97bbcb2b17ed`，可按该提交复现；独立16J及其回放未修改。

## 当前运行流程

1. 车辆必须放在N054小偷起点、车头朝地图西方W，不能从任意节点启动。前后灰度和JY61P均需正常；短按KEY2才启动。按键停止、主动制动和原故障保护沿用。
2. 起步前检查灰度有可识别线及新鲜YAW，在软件中将此时YAW与已知W方向建立参考。不向陀螺仪发送归零命令，也不以陀螺仪推算绝对XY。
3. 按固定取宝前缀运行：N054→N053→N044→N036→N035→N034→N033→N025→N015→N006→N005→N004。它实现用户的N053右转、N036左转到N033、N033右转到N006及取宝路线。N005是路段内宝藏标记，不作为灰度路口，不停车；执行表中N006→N004合并经过它。
4. 上电、READY及取宝前四路接收关闭。在N006→N004路段的有效定位进度经过N005（距N006名义150毫米）后，锁存开启四路接收，之后的行驶、转弯和藏匿保持接收。AI-1811仍由既有供电自动测距，软件未增加电源开关或激光发射控制。
5. 到N038初始藏点，按到达路线保留车头方向。轮速满足停止判据后，识别到威胁再用16J规划到下一多出口藏点，重复藏匿—转移。候选藏点为N011/N012/N038/N062。移动中的有效测距只更新威胁记忆，不中途重规划、急转或掉头。

## 定位怎样成立

- **节点由灰度与陀螺一起确认**：当前路线预计的下一节点、名义里程范围、灰度路口事件、地图相对分支和进入朝向必须一致，才更新`confirmed_node`。
- 前进读取前灰度；倒车读取后灰度，继续使用原`TravelFrame`方向换算。前后模块不是拼接成24路，也不运行两个独立纠偏环。
- 路段内XY用原编码器和预存直线路段估计。走够长度只能更新估计进度，不能单独将下一节点改为“已确认”；漏检导致超距时停车。
- 转向期间姿态标为过渡，不能拿它作为激光决策位置。转后灰度连续三次普通有效线、相对转角70°～110°、启动参考下的全局朝向误差不超过25°，才推进路线。
- 倒车是行驶方向和灰度角色交换，不是车身调头180°；直行/倒车切换检查车头朝向保持，不制造陀螺180°转动。
- JY61P原有代码仅使用转角绝对值。为避免猜测安装方向下YAW正负，第一次按地图完成的90°转弯并重新识线后，记录顺时针对应的YAW符号。后续转错方向不允许重新学习符号；原始启动参考也不会在每个路口自动重置来掩盖累计偏差。
- 读取角度和时间戳时短暂保护两个标量的一致性，并在读取之后取当前时间，避免中断更新造成新时间戳与旧角度混用或无符号年龄误判。

纯算法模块：[ThiefLocalization.c](Algorithm/MapLocalization/ThiefLocalization.c)及[头文件](Algorithm/MapLocalization/ThiefLocalization.h)。硬件采样和状态机衔接在[App_ThiefStrategy.c](User/App_ThiefStrategy.c)。运行时路线中的`expected_ports`旧字段保存度数，与历史ROM分支掩码含义不同；新模块从真实相邻道路计算左右分支，不混用该字段。

这仍是已知起点、地图序列、里程和朝向约束的定位估计。多个路口可能有相同灰度形状；车被搬动、连续漏检或名义长度误差较大时不能保证自动找回位置。陀螺和灰度不能单独提供任意起点的全局定位，也不能证明厘米级坐标精度。灰度触发点与车身中心的偏移、制动滑移和实际转动中心尚未标定，节点XY是逻辑地图锚点。

## 沿用的16J策略

沿用独立16J的579条预生成路线、每个根最多67条候选、6种追击假设、120毫秒风险档、完整转移模型数与藏点前后撤离余地排序。保持100毫秒规划保护，不把模型覆盖数称为成功概率。最新65厘米改动使FrontLaserGate.c/.h、ThiefStrategyConfig.h及ThiefRollout.c与16J原版不同；其余9个策略C/H文件仍逐字节一致。独立16J工程和回放未修改。

规划参考仍是前进674毫米/秒、倒车679毫米/秒、转弯额外768毫秒、前进/倒车切换282/274毫秒；它们来自原仿真参考，不是本次新测。实际16B控制参数、PID、转向PWM及灰度纠偏均保留。若以后修改速度和转弯参数，需同步重标定规划耗时。

四路激光接线保持：前PA3、左PB7、右PC11、后PB11；左前编码器B相PB14；日志PB10；JY61P仍为UART5 PC12/PD2、9600。TFT仍取消。不修改供电、GPIO、串口/定时器初始化或轮位映射。

四路软件检测上限统一为650毫米，仍保留50毫米下限、置信度、5帧3有效及近距2帧确认规则；650毫米以外不触发威胁。地图投影从当前估计XY出发，沿真实连接路段判断，不能穿越断路或地图外。移动时仅接受25毫秒内、时间戳不早于当前有效路段起始时刻且朝向偏差不超过5°的观测；转弯和路口过渡无效位姿不生成威胁。READY与取宝前不接收。只有停稳藏匿时才触发16J换线规划；移动检测只更新威胁记忆。距离命中点在地图内不等于识别了警方身份。

地图外围道路中心线为x=0/3300毫米、y=0/2700毫米。有效定位在上沿时屏蔽北向，下沿屏蔽南向，左沿屏蔽西向，右沿屏蔽东向；角落屏蔽两个外侧方向。前/左/右/后按车身朝向换算，倒车不交换车身朝向。外侧回波在威胁与道路清空证据处理前直接丢弃；恢复后清除旧确认历史，仅使用严格晚于恢复时刻的新帧。停止日志显示EDGE_OFF。当前规则、验证和完整文件清单见[MAP_EDGE_LASER.md](MAP_EDGE_LASER.md)。这是停用软件检测，接收与模块供电保持，不关闭模块发射。

宝藏字样过滤：N004↔N006平移时，先清除朝地图北侧文字的最外两路，再计算前后灰度位置、PID误差、路口与定位证据。向西领头屏蔽P1/P2、尾随屏蔽P11/P12；向东相反，倒车由TravelFrame交换板角色。真实南侧支路保留。转弯、转后找线及其他路段用完整读数；尤其FOLLOW但arrived=1的转后对准阶段不使用旧路段方向过滤。直行MAP_PASS及其恢复阶段继续过滤。不伪造居中线：只有文字而真实线路全白时仍判丢线。当前验证及文件清单见[TREASURE_GRAY.md](TREASURE_GRAY.md)。

## 串口确认和可调项

串口115200、8N1、文本模式。启动标识：`Thief16B_FourLaser_MapStrategy_Test ALGO=16J LOC=GYRO_GRAY`；`MAP_READY`应为START=N054、HEADING=W、FIRST=N053，`PLAN_V3 GOAL=N038`及`HIDE_V4 NODE=N038`确认新的首藏点，不再是旧N059。

停止时每500毫秒输出`LOC`，含已确认节点、地图估计XY毫米、车头方向BODY、移动方向TRAVEL、MODE、VALID、PHASE、YAW_ERR、YAW_AGE、CW_SIGN及FIXES。方向0/1/2/3对应N/E/S/W。移动期不增加连续定位格式化输出，路口事件仍由既有MT3日志记录。

主要故障：`LOC_GYRO_STALE`、`LOC_HEADING_MISMATCH`、`LOC_GRAY_MISMATCH`、`LOC_DISTANCE`、`LOC_TURN_DIRECTION`、`LOC_STEP_MISMATCH`。运行、转向、转后找线或藏匿时陀螺无有效帧/超过150毫秒即主动制动停车，不只依靠灰度继续运行。故障后需用户确认位置并重启，不自动从失效坐标继续逃跑。

定位阈值在`Algorithm/MapLocalization/ThiefLocalization.h`：150毫秒新鲜度、25°全局朝向容差、70°～110°转后相对角度窗口。里程检查沿用原导航的0.4×长度−50毫米至1.6×长度+100毫米，是较宽的名义检查，不是定位精度保证。初始45°陀螺旋转阶段随后还有灰度找线，不能把45°当成整个地图90°转向。
