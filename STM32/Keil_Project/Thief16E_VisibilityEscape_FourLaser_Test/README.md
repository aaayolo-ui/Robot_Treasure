# Thief16E：有限激光观测、定点藏匿和应急撤离

从 16D 独立复制的新实验，16D 保留。**仅编译通过，尚未完成硬件验证**。

本版解决“保守风险估计不安全就停车”和“所有藏点都在冷却就停车”两种决策问题。检测到地图内有效目标后，保持沿黑线路网撤离；若没有正时间余量的路线，就选择可走路线中保守余量较好的方案，并明确记录风险。不是保证不被抓的策略。

工程入口：`MDK-ARM/Thief16E_VisibilityEscape_FourLaser_Test.uvprojx`。
算法分类、原始来源和对比结果：[项目策略比较](../../../Docs/13_小偷策略算法分类对比_16E.md)。

## 默认行为

从 N054 朝西起步，保持原指定取宝路线：

`N054→N053→N044→N036→N035→N034→N033→N025→N015→N006→N005→N004`。

N005 不停车、不当成新增灰度路口。其后默认仍选 N023 藏匿；停稳后启用激光。地图内有效目标触发沿已选路线转移，到下一个藏点停稳，再开始检测。转移路线不在相邻节点间反复折返。

普通目标使用 3/5 帧确认；不超过 400 mm、置信度至少 20 的近距目标，允许同一通道连续两帧有效，且最近窗口内有效距离波动不超过 80 mm 时提前触发。道路投影、场界、质量和停稳状态门控保留。激光只能确认地图内物体线索，不能只凭距离证明是警方，也不把测距值直接当作接触裁判。

默认合法藏点为 N023、N039、N044、N059、N062、N063。优先避开上一个和近期暴露的藏点；无新藏点可用才应急重用。死路和单入口回环不作默认藏点，不在路段中间伪造路口。

`Algorithm/ThiefStrategy/ThiefStrategyConfig.h` 中默认启用：

- `THIEF_EMERGENCY_ESCAPE=1`：不因负的保守余量停车；允许最后选择冷却中的藏点。
- `THIEF_FAST_NEAR_CONFIRM=1`：地图内近距稳定目标提前确认。

其余候选功能默认关闭：藏点预警评分、额外警方转弯时间下界、扩大长轴十字路口藏点、固定初始藏点。比较结果没有证明这些功能更稳；相应试验入口仍可通过编译宏复核。

## 控制、引脚和日志

运动控制、PID、编码器、灰度、陀螺仪和停机控制均继承 16D，没有改变底层参数。实际控制宏仍为巡航 260 RPM、转向 PWM 550、陀螺仪阈值 4500（45°，不是转弯额外时间）。规划用的 674/679 mm/s、768 ms 转向额外耗时和 282/274 ms 换向耗时是旧标定估计，不能当作当前新实测值。

四方向激光 TX：前 PA3、左 PB7、右 PC11、后 PB11；日志 TX 为 PB10。左前编码器 B 相为 PB14，TFT 关闭。没有新增接线。

行驶期激光接收仍关闭，停稳后才启用。这继承了已有工程的电机/串口资源安排，意味着转移途中出现新来车时无法实时规避。

启动日志打印 `STRATEGY16E` 的配置开关；`PLAN_V3` 包含目标、预计耗时、保守余量、展开状态数、`DEGRADED`、`REUSED` 和计算耗时。`DEGRADED=1` 表示仍有风险，不能解释为已经安全；`REUSED=1` 表示无新藏点时应急重用。

## 编译与验证

ARM Compiler 5.06 全量编译：0 Error(s), 0 Warning(s)。Flash 43,796 B；RAM 34,368 B / 48 KiB。算法工作区 13,265 B 和 2,048 B 栈已计入 RAM，不能重复相加。搜索固定 704 状态，无递归、无动态分配、算法层不操作 HAL。100 ms 预算保留，但板上计算耗时没有实测。

实际 C 算法通过 CPU 模拟器测试：10,474 项检查，0 失败；四路串口解析回归：435 项检查，0 失败。它们证明算法/解析代码在测试输入下的行为，不证明真实电气和行驶性能。详见 [验证记录](VERIFICATION.md)。

电脑回放和对比工具：`Tools/TreasurePursuitSimulator/variants/16e`。
新回放：`http://127.0.0.1:8765/variants/16e/replay.html`。

5 个未参与筛选的种子中，完整开局平均生存时间为：同速 37.832 秒，警方快 20% 时 26.948 秒；16D 分别为 17.760、15.890 秒。新旧版均未在这组复核中赢下比赛，当前主要改善是避免规划停车。

无需虚拟机或远程服务器；可选的本地 HTTP 服务仅用来观看回放。实车定位误差、惯性、转向过程中车体占用、传感器安装偏移及中断/串口耗时尚未验证。首次实车复核应先在停机状态核对地图节点、四路方向和日志，再由用户执行已有低速运动检查。
