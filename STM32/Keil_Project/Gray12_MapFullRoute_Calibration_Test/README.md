# 全图连续路线采集工程

基于用户提供的 `Gray12_DesktopBase_ReverseReturn_Test` 独立复制，集成地图路线与计时记录。原倒车工程和旧的 21 条分批采集工程均保留。**仅编译通过，尚未完成硬件验证**。

## 这次改动

- 一次从 **N081，车头朝地图上方 N** 启动，按预装地图连续运行，最终回到 N081 停车。106 条路段各走两个地理方向，共 212 项；跨不可识别的 N005 直道合并后为 210 个到达步骤，名义总长 **82.8 m**。
- 路线包含 118 次 90°转弯和 24 次前进/倒车切换。换向先主动制动，至少 80 ms 且连续两次轮速均不超过 2 RPM，再切换逻辑前后灰度及轮速映射；新行驶前端必须检测到普通有效线，否则停车报错。**这里的换向是倒车/前进切换，不是原地转 180°。**
- 沿用新倒车工程的 220 RPM 巡航目标、20 ms 控制周期、5 ms 路口观察；接近/转后起步为 100 RPM，转向 PWM=500，先转 50°再循线找正。日志验证完整 90°转弯，不能把 50°旋转阶段当成整个转弯。
- 地图规定各路口动作，取消固定第五路口返回和四次转弯历史限制。仅最终一步正常结束；黑线也可能是中间节点，不能提前结束。
- 运行中 KEY1/WK_UP/KEY2 停车，停车按键松开不会重启。启动时默认停止；全程上限 20 分钟，保留灰度、陀螺、堵转、制动、找线和地图距离异常保护。这个上限不是预计运行时间。

## 操作

1. 用户在 Keil 打开 [工程文件](MDK-ARM/Gray12_MapFullRoute_Calibration_Test.uvprojx)，自行编译和烧录。确认烧录的是这个新工程。
2. 前灰度对准 N081 起点黑线，车头朝 N。前后灰度都需接好，安装方向沿用倒车源工程；不要在任意中间节点开始。
3. 打开电脑日志采集。串口应显示 `Gray12_MapFullRoute_Calibration_Test MT3` 和 `MAP_READY R001 START=N081 HEADING=N`。实际 COM 口以电脑识别为准，115200、8N1；采集与 VOFA+ 不能同时占同一串口。
4. 用户短按一次 KEY2，正常情况下连续执行全图，中途不选路线、不搬车。故障或人工停止后不要直接从中途重启，应检查日志并重新回 N081 摆放。
5. 最终显示 `MAP_ROUTE_DONE R001 AT=N081`，MT3 的 END 参数为 3。保持接收几秒让队列发完，再 Ctrl+C 结束电脑采集。

首次实车验证应先检查前进、停稳换向、后灰度循迹、倒车左右转与预期节点一致，再进行完整长程采集。尚未通过实车验证，不保证首次就能完成全图；当前并非任意位置自动定位，漏路口后不会自动重定位。

## 计量与地图边界

所有事件时间来自 STM32，蓝牙/USB 接收延迟不参与计时。MT3 比 MT2 在末尾增加 `drive_mode`：0 前进、1 倒车；增加 REVERSE_BEGIN / REVERSE_READY。每条记录包含 run、序号、路线签名关联、步骤、N 编号、陀螺有效性、编码器累计值、队列丢失计数及 CRC。时钟回绕可处理，缺包、错误模式、损坏 CRC 和不完整换向不会作为有效标定。

节点位置采用“已知起点 + 灰度路口顺序 + 编码器距离合理性检查”，不是绝对定位。N005 宝藏不生成假的灰度事件。全部距离沿用名义地图/轮径，尚未实地标定；换向会切换传感器参考点，不能直接用下一段名义长度除换向全流程时间来宣称准确速度。分析将前进与倒车分开，路段时间、转弯流程与换向流程分别保存。

这一趟覆盖所有地理方向，但没有让每条路的每个方向都各以前进和倒车测一次。当前仿真不维护车身前后模式，因此生成配置时只使用前进样本，倒车样本留在报告中；缺少的模式/速度不能凭空补成实测值。一次运行也不能证明重复精度，需实测重复后比较波动。

## 源码和验证

- `Control/TravelFrame.*`、PID、底盘、驱动、Core 均沿用用户指定倒车工程。
- `Algorithm/MapRoute/`：N/S 表、连续路线、连通/方向/模式校验及顺序导航。
- `User/App_LineFollowExperiment.c`：连续路线状态机、前后模式切换、停止与故障保护。
- `User/MapTimingLog.*`、`MapRoutePosition.*`：源端计时、MT3、带行驶方向的里程检查。
- `System/UartDebug.*`：沿用地图采集工程的整行非阻塞入队重试，原串口和引脚不变。
