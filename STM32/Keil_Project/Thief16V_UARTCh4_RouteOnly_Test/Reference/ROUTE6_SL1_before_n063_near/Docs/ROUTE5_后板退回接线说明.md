# ROUTE5_RETRACE：前失线、后有线时沿后板退回接线

2026-10-30，当前固件 `UARTCH4_16V_ROUTE5_RETRACE`。用户确认222601日志最后实际停在N039/N040附近。原ROUTE4源码、文档、测试证据和映像备份在 `Reference/ROUTE4_before_rear_retrace/`，清单 `SNAPSHOT_SHA256.json`。未修改桌面原版或其他工程。

## 问题与证据

日志主控时间149097ms进入N039→N040；149108ms进入FRONT_WAIT(NO_LINE)；151197ms以GRAY_BOTH_NO_LINE结束。普通文本输出有截断，MT3记录经CRC校验确认末段时序，不能按混排文本的文件行序猜测主控事件时序。

失线恢复文本出现前000/后010、030，之后双000。旧RestartLineSearch在仅后板可用时仍以50RPM向前走，用不超过4°的相对航向进行纠偏。这一输入条件下无法保证前板重新接线，继续平移可能丢掉后板的最后线索。日志无法证明最初失线的机械原因，本次针对确认存在的恢复行为修复，不宣称已经找到所有实物出线原因。

另一个确定的问题：Route_StopFault清route_active后，Thief_UpdatePose退回thief_current_node（上次停靠藏点），导致LOC跳回N011。它不证明实车已经回到N011，也不能当作绝对定位。

## 本次行为

- 仅后板有紧凑真实线形时，先制动并连续两次确认实测停稳，再以50RPM为基准反向沿后板接线，左右差速仍限20RPM。后板此时是运动前端，横向误差符号反转；TravelFrame保持本趟方向，四轮目标只映射一次。
- 前板重新有紧凑线时，先制动反向运动，确认停稳并连续接线后才交回原PID。只看到一次边缘线不能绕过停稳。
- 反向恢复命令清除原前进路口武装，防止把倒回时碰到的007/E00/FFF误认作下一个节点。回到普通巡线后按原有效线样本重新武装；回退期间不提交历史、清里程起点或切换传感器帧。原带符号轮程会记录实际退回量。
- 未完成转弯时，后板可能仍压着入弯旧线，不能据此倒回或向前冲。此时沿用原原地扫线；普通入弯180ms、主旋转和正常巡线参数没有改变。
- 如果仅剩的后板线也消失，立即退出平移，复用原制动与±4°小角度扫线。保留连续双板无线2秒停车、按键和真实硬件故障停车。
- 故障前保存当前路线位置估计，故障后冻结这份坐标并标记无效，不再发布旧藏点坐标。此功能不是绝对定位或重定位。

这套恢复适用于相同传感器条件，不写N039/N040专用电机动作。原路线策略、普通PID、速度、轮速控制、激光前后1000/左右900mm、Keil配置均保持。仅生产源文件 `User/App_ThiefStrategy.c`、`Control/RestartLineSearch.c` 产生必要差异。
