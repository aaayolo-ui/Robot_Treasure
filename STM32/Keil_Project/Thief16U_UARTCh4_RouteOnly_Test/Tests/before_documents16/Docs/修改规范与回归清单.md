# 修改规范与回归清单

用户要求：每次改代码不能重蹈覆辙。此文件是当前工程持续维护的工作约束，配合本目录 `AGENTS.md` 执行。用户后续明确调整某项要求时，以最新要求为准，并同步修改此文件及测试预期。

## 固定要求与参考依据

| 项目 | 要求 | 验证依据 |
|---|---|---|
| 正常速度 | 对齐16T，不通过全面降速修灰度误停 | `Tests/test_speed16t.py`，与实际16T AXF比较正向/反向/转弯出口目标曲线 |
| 正常起步与转弯后种子 | 200 RPM；保留原巡航与灰度增益 | 16T源参数及速度比较 |
| 激光触发 | 1000 mm中心距离；原始有效上限1000 mm及安装换算分别记录 | `Tests/test_16m.c` 边界与独立几何判定 |
| 灰度恢复航向范围 | 用户指定±10°，不是任意收窄的5° | Documents14回放、±10°边界测试 |
| 藏点 | N011/N038/N035横向；N026/N063纵向 | 全藏点、两种停车朝向、正反到达测试 |
| 入中心动作 | 与转弯前相同的平均100 RPM、180 ms；刹车位移补偿单独核对 | 原参数、编码器增量和动作时序 |
| 真正停车姿态 | 延时结束不等于方向已正确；停稳、真实新鲜YAW连续确认后才标记停车准备完成 | Documents15新增回归 |
| 硬件/构建 | 原引脚、时钟、CubeMX、ARMCC5、ST-Link配置 | 工程引用检查、全量编译0错误0警告 |

200 RPM是起步种子而非所有时刻的恒定巡航目标。1000 mm中心距离与原始距离不同；前×0.9、侧+100 mm、后+150 mm的既有换算不可混淆。既有异常找线控制器的50 RPM只用于数据异常阶段，不能扩展为正常行驶限速。

每次修改工程文件前必须重新读取本规范，包括同一轮中的后续修改，不能只在对话开始时读一次。

## 每次修改的执行顺序

1. 确认准确工程路径、读取本规范与README、检查Git状态（无Git元数据就如实记录）、核对当前FW标识和源码。备份将修改的文件、原AXF、原日志及源文件散列。
2. 从日志确定触发状态、时刻、原始灰度、YAW、里程及最后故障。区分缓冲回放与当前动作，不能把故障后输出的旧TW记录当作仍在驱动。
3. 为新问题先写最小复现用例，验证原版确实在该断言失败。保存失败记录与复现脚本，不能把无效路线、错误长度或测试装置错误算成原固件缺陷。
4. 只修相关状态机/控制模块。控制算法放Control/Algorithm，应用只调度，main.c和底层硬件不扩散业务。不得用删除全部故障处理、伪造灰度、伪造节点位置来使测试通过。
5. ARMCC5全量编译，并运行新用例及受影响旧回归。模拟车辆模型必须对新增旋转/制动命令作出相应输入反馈；模型也不能直接把目标姿态强行写成已确认状态。
6. 核对每份结果的AXF、源码、测试脚本及依赖脚本SHA-256；改变固件后旧的应用结果必须重跑。纯算法未改动时可保留源码散列相符的独立算法结果。
7. 更新README、增量差异、验证报告和本清单状态。明确区分编译、离线、实车验证；由用户决定烧录与实车运行。

## 验证集合与证据范围

- `Tests/test_app_runtime.py`：原应用状态机、508种转弯、停车、回撤、重规划。
- `Tests/test_escape_completion.py`：五藏点40组合、完整路线、再次拦截；无道路方向按原规则忽略，不伪造为触发成功。
- `Tests/test_documents12.py`：噪声触发、重复起步、距离窗口与240种刹车补偿。
- `Tests/test_documents13.py`：速度连续、地图辅助找线、双板无线、激光抢占。
- `Tests/test_documents14.py`：实际6.51°故障场景、±10°恢复边界与原定位检查。
- `Tests/test_speed16t.py`：正常速度与16T目标曲线比较；未改16T时参考AXF无需重复构建。
- `Tests/test_documents15.py`：停车纠偏、停稳确认、新鲜帧、转弯出口丢读恢复；实际结果列入当前验证报告。
- `Tests/verify_snapshot.py`：最终文件改动、Keil引用、源文件、结果与固件一致性。

离线通过不保证物理车中心已经对准路口中心。180 ms对应的实际中心位置依赖安装距离、轮径、速度和刹车滑行，应通过实车校准；未完成前不能写“精确居中已验证”。
