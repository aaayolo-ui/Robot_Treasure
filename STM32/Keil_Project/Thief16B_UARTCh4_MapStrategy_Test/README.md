## 本次数据就绪修正：UARTCH4_RUN4

RUN3实车逐次接收样本已核验通道1～4均有校验正确的真实二进制帧，115200时错误0，却未返回预期的文字应答；仅靠文字应答阻止启动不符合当前只接收激光的实际需求。见 [RUN3原始样本](Evidence/20261017_run3_received_frames.txt)和[逐次接收/独立校验摘要](Evidence/20261017_run3_received_frames.json)。样本为各次尝试最前24字节，不能拼成连续流声称完整传感器验收。

- 开机停车时先以115200被动接收，使用实际AI1811Mux解析器校验通道、帧头、长度、累加校验和250ms时效。每路至少3个有效帧、首末间隔至少20ms、最新帧不超过250ms，四路同时满足才设置 `LINK=FRAMES4`。
- 被动验证最多1200ms，无配置命令发送；有溢出/串口错误会重新收集证据。四路验证不足时，回退到下方RUN3的主口优先/有效应答配置。缺一路、错误校验、只有单次数据或没有有效应答，不能靠放宽字符匹配放行。
- `FRAMES4`确认的是模块→MCU接收通道；MCU→模块文字配置命令通道仍标为 `COMMAND_ACK=UNVERIFIED`，不宣称它已修复。文字应答配置成功则显示 `LINK=ACK`。
- 开机数据只交给私有的链路验证回调，绝不送入躲藏/逃跑处理；完成验证后清理流缓存并关闭接收，仍在取宝门槛后才启用运行检测。

已通过实测帧格式回放、缺方向/损坏校验/只有一次不放行、ACK配置回退及完整Keil编译。实车复位后前/左/右/后分别收到5/5/3/5个有效帧，四轮计数清零、PWM全0、STBY=0。当前仅完成开机接收验证；未自动下载或启动电机，行驶及取宝后避障仍待验证。

## 直接使用

1. 完全断电后，把前、左、右、后激光的 T/TX 分别接回扩展板 RX1、RX2、RX3、RX4。主口 M_RX→PB6、M_TX→PB7，扩展板供电沿用已测的3.3V并共地；四只激光R/RX及扩展板TX1～TX4不接。
2. 在 Keil 打开 [Thief16B_UARTCh4_MapStrategy_Test.uvprojx](MDK-ARM/Thief16B_UARTCh4_MapStrategy_Test.uvprojx)，编译后人工下载。旧四串口/静止固件与此运行版用途不同，确认下载目标是本工程。
3. 小车摆到 **N054，车头朝N053**。上电后程序在停车状态先验证四路有效数据，不足时再自动配置扩展板；接收验证或配置成功才进入待启动状态。开机期间按住的按键会被丢弃，松开后重新短按 **KEY2** 启动。
4. **KEY1停车**。首次使用本运行版时保留人工停车能力；电脑不会自动驱动小车。原速度、循迹、定位和异常停车保护均保留。

正常开机标识：

```text
Thief16B_UARTCh4_MapStrategy_Test FW=UARTCH4_RUN4 ALGO=16J UARTCH4_READY=1 LINK=FRAMES4 MAIN=115200 FOUR_LASER DIN2=PB15 USART2=OFF
```

若四路数据验证失败且无法取得模块配置应答，输出 `UARTCH4_READY=0 FAULT=... MOTORS=OFF`，保持停车；不把“串口发送成功”当成模块设置成功。上电配置只发生在手动启动之前，行驶中没有阻塞式波特率扫描或配置发送。

## 自动配置与解码

RUN4优先被动验证四路有效数据；无需文字应答时不发送配置命令。只有被动验证不足才执行下列配置回退。

`Hardware/UartCh4.c` 使用成品板说明书的 `CHx=115200` 命令，而非裸WK2114寄存器协议。开机有限次匹配说明书列出的主口速率，尝试无结束符及CRLF，先切换并确认主口115200，再确认四个子口，收到 `OK,115200` 才继续。设置保存在成品板中，下一次开机仍会确认。配置失败码：1=MCU串口初始化，2=未收到配置应答，4/5/6=子口2/3/4配置失败，7=收到过CH0应答但新主口确认未成功。

`Algorithm/LaserMux/AI1811Mux.c` 处理 `1#`～`4#` 通道标记，支持标记后原始二进制帧及带空格的ASCII十六进制帧。只把 `AA 05` 开头、8字节、累加校验正确且未过期的帧送入原 `LaserRx_Handler`。二进制有效载荷中的 `1#` 不会改变方向；帧损坏后重新寻找通道头，不靠猜测将无方向字节归属给某一激光。

成品说明书没有完整定义多路分包、转义和帧中途插入通道头的行为。本版依据明确通道前缀和完整激光帧接收；若模块拆碎/混合导致校验失败会丢弃，不能把CPU检查当成这块成品板已无损透传的证明。

接收ISR只写512槽共享FIFO及MCU时间戳，主循环在运动控制之后每次最多处理128字节。溢出或串口错误会撤销四方向当前证据，过期字节不触发躲避；错误计数保留在原日志中，UART3蓝牙日志和UART5陀螺仪独立。
