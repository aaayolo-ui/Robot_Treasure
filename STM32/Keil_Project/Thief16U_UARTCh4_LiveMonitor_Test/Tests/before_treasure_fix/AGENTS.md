# 本工程修改前必读

当前目录为独立 `Thief16U_UARTCh4_LiveMonitor_Test` 监控分支，标识MONITOR1；保留RUN21运动算法。原始测距显示与策略启用必须独立，不能因显示数据而取消原取宝/故障/方位过滤，也不能通过改动显示宣称修复定位和倒车问题。当前验收文件为VALIDATION_MONITOR.json。

本文件适用于当前 `Thief16U_UARTCh4_ImmediateRetreat700_Test` 目录及其子目录。继承上级 `AGENTS.md`，用户当次明确要求优先。

每次修改源码、控制参数或Keil工程配置前，包括同一轮中的后续修改，都必须先重新读取 `Docs/修改规范与回归清单.md` 和当前 `README.md`，核对实际源码、固件标识和最近串口日志。禁止把历史版本说明当作当前实现。

必须遵守：

- RUN21用户明确要求灰度路口优先、里程仅辅助，覆盖历史硬里程窗口拒绝；不得仅靠里程确认新节点，必须保留源路口重武装、真实支路/航向和未确认远端身份区分。

- 未获用户要求，不改变16T已确认满意的正常速度与转弯参数，不用全面降速替代灰度问题修复。
- RUN21右CH3原始900 mm、其余三路1000 mm触发（前后+150 mm、左右+100 mm仅投影）、灰度恢复±10°、五藏点与轴向、100 RPM/180 ms入中心动作按规范执行；任何改变必须说明依据，不能悄悄改参数。
- 新故障先增加针对性用例，保留修改前失败证据，再修代码。不得删旧断言或放宽阈值来掩盖问题；用户明确改变要求时，说明测试预期随之改变的理由。
- 变更可能影响的旧回归必须通过，测试输出绑定本次AXF与源码散列。新的源码不能配旧的通过结果。
- 灰度恢复和停车测试必须覆盖实际出现的偏航、无线、反向行驶、停稳与新鲜YAW帧；禁止只测试居中、零角度、传感器恒定有效。
- 硬件接口被模拟的测试只能证明软件状态/目标输出。未进行实车验证时必须写：`仅编译通过，尚未完成硬件验证`。
- 修改后更新约束清单中的当前版本/验收状态、README、增量差异和验证报告；列出所有改动文件和未验证事项。保留当前基线，禁止自动烧录、驱动电机、占用串口、提交或推送。
